## Контекст

Контракты ответов строгие: клиент отвергает неизвестные поля. У пользователя может быть открыта старая версия приложения, и она должна работать с новым сервером до перезагрузки. Такой приём уже применяется для атрибуции публикаций.

## Решение

Новые поля в ответах отдаются только по заголовку клиента `X-Memoly-Children: 1`. Это список детей в ответе семьи, а также отметки и версия отметок в воспоминаниях. Без заголовка ответы остаются прежними. Прежний ответ семьи с одним ребёнком и прежние маршруты профиля ребёнка сохраняются для старых клиентов.

## Почему

- Добавлять поля всегда, как необязательные. Старый клиент проверяет ответ строгой схемой, лишнее поле роняет разбор ответа и сохранённого кэша. «Необязательное» защищает только того, кто читает, а не того, кто проверяет.
- Заменить единственного ребёнка списком. Это ломает ответ для всех открытых старых клиентов и сохранённый кэш сразу.
- Новая версия API с отдельными маршрутами. Это два набора маршрутов ради окна между выкладкой и перезагрузкой вкладки, а заголовок даёт то же без дублирования.

## Последствия

- Ответ зависит от заголовка. Любой запрос новой версии, где заголовок забыли, молча покажет одного ребёнка и воспоминания без отметок. Ошибки при этом не будет.
- Заголовок нужно разрешить в настройках сервера для кросс-доменных запросов, иначе браузер заблокирует запрос.
- Пока не вышел релиз очистки, поддерживаются две формы ответа и оба набора путей профиля ребёнка. Тесты должны проверять обе.
- Сохранённый кэш приложения получает новую схему. Старые записи отбрасываются один раз, а выбранный фильтр ребёнка остаётся.
