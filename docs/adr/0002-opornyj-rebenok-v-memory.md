## Контекст

У воспоминания обязательное поле ребёнка, и старая версия приложения при откате продолжает его писать. Правила проекта требуют порядок «добавить, совместимый код, убрать» (AGENTS §10).

## Решение

Поле остаётся обязательным, но перестаёт быть смыслом связи. В него пишется опорный ребёнок: первый из отмеченных, а если отметок нет — старший по созданию живой ребёнок семьи. Миграция только добавляет, без удаления и без смены обязательности существующих столбцов. Очистка поля — отдельный будущий релиз.

## Почему

- Снять обязательность или убрать поле сразу. Откат кода перестал бы быть безопасным: старая версия пишет это поле и упала бы на базе, где его уже нет или оно необязательно. Требование «старая версия продолжает работать с новой базой» было бы нарушено.
- Оставить поле источником истины, а таблицу отметок сделать дополнением. Как только отметок несколько, два источника «чей это ребёнок» расходятся, и фильтры с правами читали бы разное.

## Последствия

- В схеме остаётся столбец, который выглядит как связь, но ею не является. Новичок будет читать его как «ребёнок воспоминания». Это ловушка, пока не выйдет релиз очистки.
- Релиз очистки обязателен и должен быть назначен отдельно. Без него долг останется навсегда.
- Воспоминания, созданные старым кодом во время отката, приходят без отметок. Это принятое ограничение.
- Везде, где код брал «первого ребёнка», теперь работает «старший по созданию». Для семьи с несколькими детьми эти места по-прежнему видят одного ребёнка, пока их не переписали явно.
