**Исполнитель:** Luna. **Ревью:** Terra — визуальная проверка и доступность; при структурных изменениях Sol.
**Зависимости:** 02 приняты и слиты в main. Разрешённая параллельная волна A; читать ../PARALLEL_WORK.md.
**Цель:** Точно воспроизвести светлое направление первого варианта без расширения функциональности.
**Правила работы:** корневой `AGENTS.md`; `../PARALLEL_WORK.md`; для UI также `../ASSET_GUIDE.md`.
**Спецификация:** `../00_START_HERE.md`; дополнительно прочитать: BRANDBOOK.md, design.md §§D00–D05,D10–D11,D17–D19, design/tokens.json, design/ui-copy.ru.json.
**Стек:** выбранный Vibe — Bun/Hono, PostgreSQL/Prisma, React/Vite, общие Zod-контракты.

## Границы
Этот блок — единица сдачи, но внутри выполнять маленькие шаги и сохранять контрольные результаты. Пакет содержит спецификацию; пути ниже — ожидаемые создаваемые/изменяемые файлы, не утверждение их наличия до начала. Если аналогичный файл уже существует по REPO_MAP, использовать его и указать mapping, не создавать дубль. Все пути относятся к корню проекта.

MVP: только личный бот, Telegram Mini App, четыре формата, full/viewer, семейные лайки. Без AI, групп, платежей и реализации будущих платформ. Новые семейные данные — только synthetic fixtures до приёмки закрытого пилота.

## Файлы
webapp/src/styles/tokens.css; components/ui; features/session/components; features/feed/components/FeedShell.tsx; components/BottomNavigation.tsx; адаптер использования уже принятого HostBridge (без изменения его реализации); dev-onlyfixtures; visualtests.

## Потребляемые и производимые интерфейсы
Потребляет tokens/copy и semantic props. Производит FeedShell,DateHeading,MemoryCardFrame,BottomNavigation,AddSheet,AvatarLetter,EmptyState,InlineError. Компоненты не требуютTelegramSDK.

## Порядок выполнения
1. Подключить Inter из официального источника, сохранив лицензионное уведомление, и настроить системный fallback. Не копировать частные файлы шрифтов из чужих проектов.
2. Использовать общие WebP-иконки из assets/icons и WebpIcon с aria-label на кнопках; не добавлять SVG/Lucide/Hugeicons. Применить semantic variables из tokens. Сохранить выбранное семейство shadcn-примитивов. Удалить демонстрационный dashboard из активного продукта, не переносить его sidebar в Mini App.
3. Собрать FeedShell: max-width480, gutter16, заголовок, профиль ребёнка, фильтры и три позиции нижней панели. HostBridge возвращает нормализованные insets без двойного padding. Системные панели не рисовать.
4. В full-режиме центр — единственный плюс; в viewer-режиме — неинтерактивная метка «Просмотр». В AddSheet нет календаря, событий или AI.
5. Создать каркас карточки, дату, ошибки, skeleton и пустой экран как небольшие повторно используемые компоненты. Системные тексты брать из утверждённого файла.
6. Создать только development-страницу синтетических fixtures для рендера без Telegram. Её не должно быть в production. Снять скриншоты360/390/430px и при увеличении текста200%.
7. Проверить зоны44px, контраст, aria, focus, закрытие по Back и reduced motion. Не заменять реальные ограничения роли тестовым переключателем в production.

## Обязательные сценарии проверки
F06.1 Все семантические цвета соответствуют tokens. F06.2 В панели три позиции и один плюс. F06.3 У viewer нет действия добавления. F06.4 Длинное имя не перекрывает заголовок. F06.5 На360px нет горизонтальной прокрутки всей страницы. F06.6 Dialog правильно удерживает и возвращает focus. F06.7 При тексте200% основные действия доступны. F06.8 Fixture-маршрут отсутствует в production.

## Проверочный цикл каждого изменения
- [ ] Найти существующие границы и перечислить затронутые файлы до редактирования.
- [ ] Для каждого сценария выше написать или уточнить тест на ближайшем подходящем уровне.
- [ ] Запустить новый тест до реализации и убедиться, что падение относится к нужному поведению, а не к случайной ошибке окружения.
- [ ] Реализовать минимальное изменение в указанном модуле, не менять контракт без согласования его потребителей.
- [ ] Запустить тот же тест, затем связанные проверки из плана области влияния.
- [ ] Проверить diff и выполнить самостоятельный review. При назначенном Sol review получить отдельный проход без опоры только на отчёт исполнителя.
- [ ] Записать команды, результаты и ограничения в отчёт по `../review/BLOCK_REPORT.md`.
- [ ] Передать владельцу результат и остановиться до следующего блока. Commit — в своей ветке, без автоматического merge/deploy.

## Команды проверки
Новые тестовые файлы с указанными именами создаёт этот блок. Фильтр должен реально находить тесты: ноль найденных тестов не является успехом. Если выбранный Vibe использует другую эквивалентную команду, обновить REPO_MAP/verification-map и привести фактический запуск.

