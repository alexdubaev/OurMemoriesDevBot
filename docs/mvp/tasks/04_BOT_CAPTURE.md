# Блок 04 — Автопубликация заметок и фотографий из личного бота

**Исполнитель:** Terra. **Ревью:** Sol — durable inbox, album races и проверки прав.
**Зависимости:** 03, 06 приняты и слиты в main.
**Цель:** Первый вертикальный сценарий: сообщение/фото боту создаёт одну доступную семье запись без AI.
**Правила работы:** корневой `AGENTS.md`; `../PARALLEL_WORK.md`; для UI также `../ASSET_GUIDE.md`.
**Спецификация:** `../00_START_HERE.md`; дополнительно прочитать: TELEGRAM_BOT_SETUP.md, 04_TELEGRAM.md, 02_ARCHITECTURE.md §§5–6, 03_DATA_API.md.
**Стек:** выбранный Vibe — Bun/Hono, PostgreSQL/Prisma, React/Vite, общие Zod-контракты.

## Границы
Этот блок — единица сдачи, но внутри выполнять маленькие шаги и сохранять контрольные результаты. Пакет содержит спецификацию; пути ниже — ожидаемые создаваемые/изменяемые файлы, не утверждение их наличия до начала. Если аналогичный файл уже существует по REPO_MAP, использовать его и указать mapping, не создавать дубль. Все пути относятся к корню проекта.

MVP: только личный бот, Telegram Mini App, четыре формата, full/viewer, семейные лайки. Без AI, групп, платежей и реализации будущих платформ. Новые семейные данные — только synthetic fixtures до приёмки закрытого пилота.

## Файлы
backend/src/modules/telegram/{index.ts,transport/webhook.ts,application,infrastructure,__fixtures__}/; inbox/source migration; outbox handlers; jobs/worker wiring; bot config script с dry-run; backend env schema/example с `TELEGRAM_BOT_EXPECTED_USERNAME=OurMemoriesDevBot` и пустыми secret placeholders.

## Потребляемые и производимые интерфейсы
Потребляет Memories/Media/FamilyAccess. Производит acceptUpdate/processUpdate и source mapping, receipt buttons с record deep link. grammY применяется для типов/API, не как хранилище важных sessions.

## Порядок выполнения
1. Инициализировать Telegram adapter только из server-side env. До polling/webhook вызвать `getMe`, потребовать username `OurMemoriesDevBot` и использовать возвращённый numeric id как `bot_id`; mismatch → fail-fast. Ни token, ни webhook secret не логировать.
2. Проверить секрет webhook и размер тела. Нормализовать событие, записать inbox и задание в одной транзакции. Вернуть HTTP 200 только после commit. Содержимое не писать в логи.
3. Добавить команды /start, /help, /app, /privacy и /cancel, пилотный допуск и открытие приглашения. Обычный текст создаёт заметку, фото с подписью — фотографическую запись. Групповые сообщения не сохраняются.
4. Повтор Telegram update или source message возвращает существующий результат. Повтор подтверждения ботом допустим при аварии, второй пост — нет. Для ошибки429 учитывать retry_after.
5. Собрать фотоальбом через состояние PostgreSQL: окно тишины1,5секунды, начальное ожидание максимум8секунд. Поздние элементы обработать по04_TELEGRAM. Состояние должно пережить перезапуск.
6. Проверить роль перед импортом и повторно перед публикацией. Пользователь, которому отозвали доступ, не может опубликовать давно принятое задание. Не принимать материалы без активной семьи.
7. Файл до20МБ скачать потоково через media-модуль. Для слишком большого видео подготовить корректное действие загрузки через Mini App; работа этой страницы сдаётся блоком09. Не объявлять этот переход готовым раньше.
8. Отправить receipt только после проверенной копии. Различать «Получено» и «Сохранено». Не рассылать уведомления всем родственникам.

## Обязательные сценарии проверки
F04.1 Текст создаёт одну заметку. F04.2 Фото с caption создаёт одну фотографическую запись. F04.3 Десять повторов одного update не создают дополнительные записи. F04.4 Три фото одного альбома сохраняют порядок. F04.5 Перезапуск между частями альбома не теряет их. F04.6 Позднее фото добавляется без дубликата. F04.7 Смешанный альбом обрабатывается по оговорённой политике. F04.8 Содержимое группы не сохраняется. F04.9 Viewer и отозванный участник не публикуют. F04.10 Ошибка БД до принятия возвращает неуспех. F04.11 Ошибка провайдера не раскрывает токен. F04.12 `getMe` с токеном другого бота останавливает запуск до polling/webhook. F04.13 config dry-run показывает `@OurMemoriesDevBot` и URL, но не secret values.

## Что показать владельцу
В уже созданный development-бот `@OurMemoriesDevBot` отправить заметку и фотографию после того, как владелец отдельно настроил `TELEGRAM_BOT_TOKEN` в secret environment. В API видны ровно две записи. Повтор того же fixture не создаёт третью.

## Критерий готовности
Есть результаты живой проверки на синтетических данных и интеграционных тестов повторной доставки. Меню бота не обещает отсутствующие функции.

## Стоп-условия
Не подключать групповые чаты, AI, распознавание или userbot. Не создавать второй development-бот. Не вызывать `setWebhook` на пилотный/production URL без владельца. Не просить владельца вставлять token в prompt или Markdown.

Невозможность запустить обязательный тест отмечается `BLOCKED` с причиной; не заменять его проверкой синтаксиса. Успех в локальной БД не доказывает готовность production-конфигурации.
