# Блок 09 — Добавление из Mini App, редактирование и удаление

**Исполнитель:** Terra; отдельные формы — Luna. **Ревью:** Sol — finalize/permission/дубли и destructive actions.
**Зависимости:** 07, 08 приняты и слиты в main.
**Цель:** Обеспечить минимальное добавление через Mini App, включая видео больше20МБ, и безопасные правки.
**Правила работы:** корневой `AGENTS.md`; `../PARALLEL_WORK.md`; для UI также `../ASSET_GUIDE.md`.
**Спецификация:** `../00_START_HERE.md`; дополнительно прочитать: 01_PRODUCT.md §§6,8–9, design.md §§D11–D12, 03_DATA_API.md §5, 05_STORAGE_SECURITY.md §§3–5,8.
**Стек:** выбранный Vibe — Bun/Hono, PostgreSQL/Prisma, React/Vite, общие Zod-контракты.

## Границы
Этот блок — единица сдачи, но внутри выполнять маленькие шаги и сохранять контрольные результаты. Пакет содержит спецификацию; пути ниже — ожидаемые создаваемые/изменяемые файлы, не утверждение их наличия до начала. Если аналогичный файл уже существует по REPO_MAP, использовать его и указать mapping, не создавать дубль. Все пути относятся к корню проекта.

MVP: только личный бот, Telegram Mini App, четыре формата, full/viewer, семейные лайки. Без AI, групп, платежей и реализации будущих платформ. Новые семейные данные — только synthetic fixtures до приёмки закрытого пилота.

## Файлы
webapp/src/features/composer/; memoryeditor; uploadclient; deeplinkrouting; tests; webapp/e2e/composer.spec.ts.

## Потребляемые и производимые интерфейсы
Потребляет uploads/finalize/create/update/delete API. Загружаемые файлы не требуют Telegram ID. Голос записывается в боте, а не через WebView MediaRecorder.

## Порядок выполнения
1. AddSheet открывает системный выбор фото/видео либо форму заметки. Голос открывает бота. Разрешить до10 фото или одно видео; смешанный выбор объяснить и отклонить.
2. Выполнить reserve → PUT → finalize → logical memory. Показать прогресс, отмену и ошибку, сохранив подпись в памяти формы. Один idempotency key относится к одной логической попытке.
3. Не публиковать до подтверждённой копии. При отказе S3 не показывать успех. Ссылка из бота для большого видео открывает composer без секретных файловых URL.
4. Редактор меняет body/date с expectedVersion. При сетевой ошибке введённое не теряется; при409 пользователь видит конфликт. Замена вложений не реализуется.
5. Подтверждение удаления объясняет видимость для всей семьи и отдельный исходник Telegram. После успеха удалить карточку из кэша; физическая очистка выполняется надёжным worker.
6. Viewer не открывает composer даже прямым route. Сервер также возвращает403. Старый upload-ticket не даёт права завершить публикацию после отзыва.
7. Проверить клавиатуру iOS, textarea16px, кнопки над safe area и подтверждение ухода с несохранённой формы. Постоянной offline-очереди нет.

## Обязательные сценарии проверки
F09.1 Прямая заметка не вызывает Bot API. F09.2 Фото создаёт одну запись после finalize. F09.3 Ролик30МБ загружается напрямую; бот предлагает этот путь. F09.4 Файл101МБ отклонён клиентом и сервером. F09.5 Отмена приводит к очистке reservation. F09.6 Двойной submit не создаёт дубликат. F09.7 Устаревшая версия вызывает конфликт. F09.8 Правка подписи не меняет хеш файла. F09.9 Удаление скрывает запись у семьи. F09.10 Viewer не может выполнить ручной POST.

## Проверочный цикл каждого изменения
- [ ] Найти существующие границы и перечислить затронутые файлы до редактирования.
- [ ] Для каждого сценария выше написать или уточнить тест на ближайшем подходящем уровне.
- [ ] Запустить новый тест до реализации и убедиться, что падение относится к нужному поведению, а не к случайной ошибке окружения.
- [ ] Реализовать минимальное изменение в указанном модуле, не менять контракт без согласования его потребителей.
- [ ] Запустить тот же тест, затем связанные проверки из плана области влияния.
- [ ] Проверить diff и выполнить самостоятельный review. При назначенном Sol review получить отдельный проход без опоры только на отчёт исполнителя.
- [ ] Записать команды, результаты и ограничения в отчёт по `../review/BLOCK_REPORT.md`.
- [ ] Передать владельцу результат и остановиться до следующего блока. Commit — в своей ветке, без автоматического merge/deploy.

## Команды проверки
Новые тестовые файлы с указанными именами создаёт этот блок. Фильтр должен реально находить тесты: ноль найденных тестов не является успехом. Если выбранный Vibe использует другую эквивалентную команду, обновить REPO_MAP/verification-map и привести фактический запуск.
```bash
bun run test:webapp
bun run --cwd webapp e2e -- composer.spec.ts
bun run test:backend:integration -- src/modules/media/media-access.integration.test.ts
```

## Что показать владельцу
Загрузить на iPhone видео больше20МБ через Mini App, открыть вторым участником, изменить подпись и удалить после подтверждения.

## Критерий готовности
Все показанные кнопки имеют рабочие пути. Неподдерживаемое действие не открывает пустой экран.

## Стоп-условия
Не делать монтаж, запись звука внутри WebView, импорт всей галереи или оплату.

Невозможность запустить обязательный тест отмечается `BLOCKED` с причиной; не заменять его проверкой синтаксиса. Успех в локальной БД не доказывает готовность production-конфигурации.
