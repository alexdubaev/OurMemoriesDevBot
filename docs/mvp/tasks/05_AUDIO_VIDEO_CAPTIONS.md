# Блок 05 — Голос, видео и привязка подписи

**Исполнитель:** Terra. **Ревью:** Sol — decoder sandbox, long jobs и связь caption с записью.
**Зависимости:** 04 приняты и слиты в main. Разрешённая параллельная волна B; читать ../PARALLEL_WORK.md.
**Цель:** Голос и видео публикуются с исходниками и совместимыми производными; подпись относится к явно выбранной записи.
**Правила работы:** корневой `AGENTS.md`; `../PARALLEL_WORK.md`; для UI также `../ASSET_GUIDE.md`.
**Спецификация:** `../00_START_HERE.md`; дополнительно прочитать: 04_TELEGRAM.md §§5–9, 05_STORAGE_SECURITY.md §§3–4, design.md §§D07–D08.
**Стек:** выбранный Vibe — Bun/Hono, PostgreSQL/Prisma, React/Vite, общие Zod-контракты.

## Границы
Этот блок — единица сдачи, но внутри выполнять маленькие шаги и сохранять контрольные результаты. Пакет содержит спецификацию; пути ниже — ожидаемые создаваемые/изменяемые файлы, не утверждение их наличия до начала. Если аналогичный файл уже существует по REPO_MAP, использовать его и указать mapping, не создавать дубль. Все пути относятся к корню проекта.

MVP: только личный бот, Telegram Mini App, четыре формата, full/viewer, семейные лайки. Без AI, групп, платежей и реализации будущих платформ. Новые семейные данные — только synthetic fixtures до приёмки закрытого пилота.

## Потребляемые и производимые интерфейсы
Потребляет сохранённые MediaAsset и Memories.updateMemory. Производит браузерно-совместимые playback M4A/MP4, duration/MIME metadata, 48 измеренных значений waveform и CaptionRequest, привязанный к сообщению, пользователю, семье и версии записи. Этот блок готовит файлы для HTML5 media; собственного проигрывателя/decoder здесь нет.

## Порядок выполнения
1. Определить технический формат voice, audio, video, video_note и разрешённых документов по04_TELEGRAM. Создать source mapping и сохранить оригинал. Распознавание речи не подключать.
2. Проверить контейнер, размер, длительность и кодек через ffprobe. FFmpeg запускается без интерполяции shell-строк, с лимитами памяти, CPU, временного диска и времени. Одно тяжёлое кодирование одновременно. Использовать heartbeat lease.
3. Голос преобразовать в M4A/AAC; измерить48 значений амплитуды и сохранить duration. Видео привести к совместимому MP4 либо remux с корректным Content-Type и duration. Результат должен воспроизводиться стандартными HTML5 `<audio>`/`<video>` на целевых WebView; не реализовывать decoder/player engine. Исходный хеш не меняется. Состояние производной не смешивать с сохранностью оригинала.
4. Добавить подпись через точный reply на исходное медиа либо на конкретный ForceReply-запрос. TTL10минут, привязка к requester, family и expectedVersion. Обычное соседнее сообщение остаётся заметкой.
5. Замена прежней подписи явно обозначена. Устаревшая версия возвращает409. Отмена и истечение запроса не перехватывают обычную переписку. Чужой callback отклоняется.
6. Видео больше лимита облачного Bot API получает понятный путь прямой загрузки. Не создавать опубликованное воспоминание без доступного оригинала. Telegram caption сохранять без переписывания.
7. Не синхронизировать автоматически изменения и удаления исходного сообщения; пояснить отдельную копию в справке.

## Обязательные сценарии проверки
F05.1 OGG/Opus превращается в M4A/AAC, который открывается стандартным HTML5 audio fixture; исходный хеш совпадает, waveform содержит измеренные peaks. F05.2 MOV/HEVC преобразуется в HTML5-compatible MP4 с правильной ориентацией и звуком. F05.3 Превышение длительности или байтов отклоняется. F05.4 Голос и следующий обычный текст создают две записи; reply меняет подпись голоса. F05.5 Ответ на старый prompt не правит последнее голосовое. F05.6 Чужой callback запрещён. F05.7 Изменённая версия даёт409. F05.8 Остановка задания не создаёт второй пост. F05.9 Ошибка preview не уничтожает оригинал. F05.10 Нет вызовов AI или транскрипции.

- [ ] Для каждого сценария выше написать или уточнить тест на ближайшем подходящем уровне.
- [ ] Запустить новый тест до реализации и убедиться, что падение относится к нужному поведению, а не к случайной ошибке окружения.
- [ ] Реализовать минимальное изменение в указанном модуле, не менять контракт без согласования его потребителей.
- [ ] Запустить тот же тест, затем связанные проверки из плана области влияния.
- [ ] Проверить diff и выполнить самостоятельный review. При назначенном Sol review получить отдельный проход без опоры только на отчёт исполнителя.
- [ ] Записать команды, результаты и ограничения в отчёт по `../review/BLOCK_REPORT.md`.
- [ ] Передать владельцу результат и остановиться до следующего блока. Commit — в своей ветке, без автоматического merge/deploy.

## Что показать владельцу
Отправить голос, затем обычную заметку и отдельно подпись через reply. В результате есть голос с подписью и самостоятельная заметка. Воспроизведение в живом Telegram сдаётся после подключения интерфейса.

## Критерий готовности
Серверные задания и подписи проверены. Проверка воспроизведения на реальных iOS/Android завершается блоками07 и11; до неё не заявлять совместимость доказанной.

## Стоп-условия
Не добавлять монтаж, фоновые видеозагрузки и редактор звука. FFmpeg проверяется реальным бинарным файлом, а не только mock.

Невозможность запустить обязательный тест отмечается `BLOCKED` с причиной; не заменять его проверкой синтаксиса. Успех в локальной БД не доказывает готовность production-конфигурации.
