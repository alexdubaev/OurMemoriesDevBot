# Блок 07 — Живая лента, просмотр фото и медиаплееры

**Исполнитель:** Terra; локальные карточки можно поручить Luna. **Ревью:** Terra — UI/integration; Sol — private media и auth-boundary.
**Зависимости:** 05, 08 приняты и слиты в main.
**Цель:** Подключить к принятому интерфейсу реальные данные семейной ленты и безопасные медиаплееры.
**Правила работы:** корневой `AGENTS.md`; `../PARALLEL_WORK.md`; для UI также `../ASSET_GUIDE.md`.
**Спецификация:** `../00_START_HERE.md`; дополнительно прочитать: design.md §§D04–D10,D13,D16–D19, 03_DATA_API.md §§3,5,7, 05_STORAGE_SECURITY.md §5.
**Стек:** выбранный Vibe — Bun/Hono, PostgreSQL/Prisma, React/Vite, общие Zod-контракты.

## Границы
Этот блок — единица сдачи, но внутри выполнять маленькие шаги и сохранять контрольные результаты. Пакет содержит спецификацию; пути ниже — ожидаемые создаваемые/изменяемые файлы, не утверждение их наличия до начала. Если аналогичный файл уже существует по REPO_MAP, использовать его и указать mapping, не создавать дубль. Все пути относятся к корню проекта.

MVP: только личный бот, Telegram Mini App, четыре формата, full/viewer, семейные лайки. Без AI, групп, платежей и реализации будущих платформ. Новые семейные данные — только synthetic fixtures до приёмки закрытого пилота.

## Файлы
webapp/src/features/feed/api.ts, queries и components; webapp/src/features/memory/; webapp/src/platform/media/; wrapper PhotoSwipe; композиция маршрутов; webapp/e2e/feed.spec.ts.

## Потребляемые и производимые интерфейсы
Потребляет MemoryDto/Page и относительные защищённые пути медиа. Производит FeedPage, четыре типа MemoryCard, MemoryDetail, MediaViewer и единый координатор воспроизведения.

## Порядок выполнения
1. Валидировать ответы API через Zod. Query keys включают семью и фильтр; выход и отзыв прав очищают кэш и object URLs. Не копировать DTO вручную.
2. Подключить keyset pagination по20 записей, дедупликацию по ID, сохранение scroll anchor и баннер новых записей. Обновлять только видимую страницу и при возвращении focus.
3. Собрать реальные карточки по design.md. Подпись ограничена четырьмя строками, заметка восемью с переходом в деталь. Даты показываются в часовом поясе семьи.
4. Лайк обновляется оптимистично с откатом при ошибке. Сервер получает желаемое boolean-состояние. Ошибка загрузки не убирает уже прочитанные карточки.
5. Подключить lazy PhotoSwipe v5 только к фотографиям. Использовать защищённые пути, Back/Close/focus и полное изображение contain. Отдельную общую галерею не создавать.
6. **Не разрабатывать media engine.** Использовать стандартный `HTMLAudioElement`/`HTMLVideoElement`; наше приложение реализует только React-контролы. Видео: poster, Play/Pause, seek, `current / total`, fullscreen, `playsInline`, без autoplay и без собственного volume-контрола в MVP. Голос: Play/Pause44, 48 измеренных waveform peaks, seek по waveform, duration и подпись; при отсутствии peaks — progress slider. Один общий MediaPlaybackCoordinator гарантирует, что одновременно играет только один audio/video.
7. Скрывать native controls только после проверки custom controls; при реальном blocker на поддерживаемом WebView разрешён fallback `controls`, но не новый decoder/player framework без отдельного решения. Backend source обязан поддерживать авторизованный Range/206; не передавать browser'у bot token или Telegram file URL.
8. После отзыва доступа/hidden Mini App/закрытия detail остановить плеер, освободить object URL/source, очистить семейный кэш и показать закрытый доступ. Проверить Play/Pause/Seek/Fullscreen/Back на реальных iOS и Android Telegram, включая подготовленные AAC и MP4.

## Обязательные сценарии проверки
F07.1 СемьяA видит все четыре типа своих записей; семьяB не попадает в кэш. F07.2 Более40 записей пролистываются без дублей. F07.3 Новый пост не сбрасывает чтение старых. F07.4 Viewer ставит лайк, но не редактирует. F07.5 Ошибка лайка откатывает UI. F07.6 Текст безопасно экранирован. F07.7 Второе audio/video приостанавливает первое; скрытие Mini App ставит активное media на паузу. F07.8 Seek голоса по waveform и видео использует корректный Range/206 без полной повторной загрузки. F07.9 Закрытие PhotoSwipe возвращает focus и scroll. F07.10 Отзыв membership прекращает новые чтения и останавливает media. F07.11 Voice card показывает Play/Pause, waveform/fallback progress, duration и подпись без отдельного native `<audio controls>` UI. F07.12 Video detail показывает наши Play/Pause, seek, время и fullscreen поверх HTML5 video; autoplay отсутствует.

## Что показать владельцу
На телефоне отправить боту фото, голос, текст и ролик. Открыть Mini App вторым участником, просмотреть записи, прослушать голос и поставить сердечко.

## Критерий готовности
В production нет mock-постов. Все четыре типа и их состояния работают. Визуальная приёмка выполнена.

## Стоп-условия
Не добавлять список лайкнувших, комментарии, поиск или отдельную галерею. Не писать собственные кодеки, streaming engine, buffering engine или плеер «с нуля» и не подключать тяжёлую player-библиотеку без воспроизводимого blocker и отдельного согласования. Отсутствие проверки на телефоне явно отмечается как блокер релиза.

Невозможность запустить обязательный тест отмечается `BLOCKED` с причиной; не заменять его проверкой синтаксиса. Успех в локальной БД не доказывает готовность production-конфигурации.
