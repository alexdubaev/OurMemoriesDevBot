# Блок 10 — Выгрузка, удаление и испытание отказов

**Исполнитель:** Sol. **Ревью:** Sol — независимый destructive/data-loss review.
**Зависимости:** 09 приняты и слиты в main.
**Цель:** До приглашения реальных семей подтвердить, что данные можно забрать, удалить и восстановить после сбоя.
**Правила работы:** корневой `AGENTS.md`; `../PARALLEL_WORK.md`; для UI также `../ASSET_GUIDE.md`.
**Спецификация:** `../00_START_HERE.md`; дополнительно прочитать: 05_STORAGE_SECURITY.md, 07_DELIVERY.md §§8–10, 09_ACCEPTANCE.md.
**Стек:** выбранный Vibe — Bun/Hono, PostgreSQL/Prisma, React/Vite, общие Zod-контракты.

## Границы
Этот блок — единица сдачи, но внутри выполнять маленькие шаги и сохранять контрольные результаты. Пакет содержит спецификацию; пути ниже — ожидаемые создаваемые/изменяемые файлы, не утверждение их наличия до начала. Если аналогичный файл уже существует по REPO_MAP, использовать его и указать mapping, не создавать дубль. Все пути относятся к корню проекта.

MVP: только личный бот, Telegram Mini App, четыре формата, full/viewer, семейные лайки. Без AI, групп, платежей и реализации будущих платформ. Новые семейные данные — только synthetic fixtures до приёмки закрытого пилота.

## Файлы
backend/src/modules/privacy/; операционные scripts family-export/family-erase/restore-check; обработчики удаления outbox; контракты manifest экспорта; backup runbook и отчёты проверки.

## Потребляемые и производимые интерфейсы
Потребляет owner-guard и публичные действия Memories/Media. Производит ZIP с UTF-8 manifest и оригиналами, удаление с tombstone ledger. Большая админ-панель не требуется.

## Порядок выполнения
1. Реализовать проверяемый запрос владельца через поддержку. Команда экспорта принимает конкретные familyId/requesterId и пишет аудит. ZIP приватен, срок выдачи72часа.
2. Manifest содержит дату, подпись, порядок вложений и хеши private-storage объектов. Telegram-only video reference не является backup-копией и не обещает экспорт видео; архив не содержит secrets, данных других семей или удалённых записей.
3. Удаление семьи сначала прекращает доступ, затем создаёт durable cleanup оригиналов, производных и экспортов. Для Telegram-only video удаляется encrypted reference/pointer; уже доставленное ботом сообщение нельзя отозвать из личного чата. Удаление строк не теряет object keys.
4. Добавить очистку inbox после72часов, pending uploads и captions после24часов, экспортов после72часов. Логи14дней, backup30дней. Сроки в конфигурации и документации согласованы.
5. Выполнить backup/restore в изолированном окружении на synthetic family. Сравнить хеши четырёх типов, текст, даты и права. Применить tombstones до открытия восстановленного сервиса.
6. Проверить остановку worker после записи объекта до DB finalize, после receipt до completion, отказ S3, потерю lease, отзыв роли во время импорта, ошибку удаления и отказ БД до webhook accept.
7. Проверить отсутствие контента и токенов в логах, приватность bucket/БД, шифрование at rest. Подготовить операционный runbook без вымышленных реквизитов.

## Обязательные сценарии проверки
F10.1 ЭкспортA не содержит материаловB. F10.2 Хеши оригиналов после распаковки совпадают. F10.3 Экспорт доступен только owner. F10.4 Повтор удаления идемпотентен. F10.5 Неудача удаления сохраняет key и повтор задания. F10.6 Restore возвращает живые записи и применяет tombstones. F10.7 Остановка worker не дублирует пост. F10.8 Проверка логов не находит secrets/контент. F10.9 Reconciliation не удаляет валидный объект соседней семьи.

## Проверочный цикл каждого изменения
- [ ] Найти существующие границы и перечислить затронутые файлы до редактирования.
- [ ] Для каждого сценария выше написать или уточнить тест на ближайшем подходящем уровне.
- [ ] Запустить новый тест до реализации и убедиться, что падение относится к нужному поведению, а не к случайной ошибке окружения.
- [ ] Реализовать минимальное изменение в указанном модуле, не менять контракт без согласования его потребителей.
- [ ] Запустить тот же тест, затем связанные проверки из плана области влияния.
- [ ] Проверить diff и выполнить самостоятельный review. При назначенном Sol review получить отдельный проход без опоры только на отчёт исполнителя.
- [ ] Записать команды, результаты и ограничения в отчёт по `../review/BLOCK_REPORT.md`.
- [ ] Передать владельцу результат и остановиться до следующего блока. Commit — в своей ветке, без автоматического merge/deploy.

## Команды проверки
Новые тестовые файлы с указанными именами создаёт этот блок. Фильтр должен реально находить тесты: ноль найденных тестов не является успехом. Если выбранный Vibe использует другую эквивалентную команду, обновить REPO_MAP/verification-map и привести фактический запуск.
```bash
bun run test:backend:integration -- src/modules/privacy/privacy.integration.test.ts
bun run test:backend:integration -- src/modules/media/deletion.integration.test.ts
bun run test:contracts
```

## Что показать владельцу
Показать ZIP синтетической семьи, отчёт восстановления с хешами и тест повторного удаления. Не выполнять это как демонстрацию на настоящих семейных данных.

## Критерий готовности
Есть доказательство восстановления и отслеживаемой очистки. Основные отказы имеют понятные действия оператора.

## Стоп-условия
Destructive-команды над реальными данными требуют отдельного явного запроса. Не обещать мгновенное удаление всех резервных копий.

Невозможность запустить обязательный тест отмечается `BLOCKED` с причиной; не заменять его проверкой синтаксиса. Успех в локальной БД не доказывает готовность production-конфигурации.
