# Продуктовая спецификация

## 1. Цель и критерий пользы
Взрослый отправляет боту момент и спустя несколько секунд видит его в общей семейной ленте. Второй участник семьи видит ту же запись, другую семью — никогда. Сервис не оценивает развитие ребёнка, не интерпретирует содержание и ничего не дописывает за человека.

Результат MVP: 3–10 независимых семей могут пользоваться лентой минимум две недели без ручного исправления БД разработчиком. Это проверяемая цель пилота, не обещание доступности 24/7 или сохранности «навсегда».

## 2. Форматы
| Формат | Содержимое | Правило публикации |
|---|---|---|
| Фото | 1–10 фотографий и одна общая подпись | Одно фото или фотоальбом = одна запись |
| Видео | Один ролик, превью, длительность, подпись | Каждый ролик = отдельная запись |
| Голос | Исходное голосовое и необязательная подпись | Голос не заменяется текстом; расшифровки нет |
| Заметка | Текст до 8 000 Unicode code points | Обычное сообщение, не команда, = запись |

Подпись — поле самой записи. Это не ветка обсуждения и не сообщения родственников под постом. Все тексты сохраняются как обычный текст, без выполнения HTML и без AI-редактирования. Ссылки не вызывают серверной загрузки веб-страниц.

Смешанные альбомы Telegram из фото и видео: поддержать предсказуемый безопасный вариант — отдельная запись на каждый элемент. Не объединять их автоматически в сложный медиа-пост; бот сообщает число созданных записей. Фотоальбом без видео объединяется. См. точный протокол в `04_TELEGRAM.md`.

## 3. Семейное пространство и участники
Внутренний пользователь приложения имеет собственный UUID и внешнюю Telegram-идентичность. Приглашённые входят отдельно; логин/пароль семьи не существует. Лента принадлежит семье, авторство принадлежит пользователю.

| Действие | Полный доступ | Просмотр |
|---|---:|---:|
| Смотреть ленту и медиа своей семьи | Да | Да |
| Ставить / снимать свой лайк | Да | Да |
| Сохранять доступный файл себе | Да | Да |
| Отправлять записи через бота и Mini App | Да | Нет |
| Редактировать текст и дату любой записи семьи | Да | Нет |
| Удалять любую запись семьи с подтверждением | Да | Нет |
| Видеть список участников | Да | Да |
| Приглашать, менять роли и удалять участников | Только владелец семьи | Нет |
| Менять профиль ребёнка, название, часовой пояс | Только владелец семьи | Нет |
| Выгрузить весь архив / запросить удаление семьи | Только владелец семьи | Нет |

«Полный доступ» означает полный доступ к содержимому, не глобальное администрирование сервиса. Владелец — один участник с ролью `full`, на которого указывает `families.owner_user_id`, а не третья роль. Другим полным участникам нельзя случайно удалить владельца или выдать права. На экране его строка дополнительно подписана «Создатель семьи». Передача владения в MVP только через проверяемую операционную процедуру с подтверждением обеих сторон; отдельного интерфейса нет.

Просмотр и скачивание не равны защите от копирования: скриншоты и уже загруженные родственником файлы отозвать нельзя. Не обещать обратное.

## 4. Первый запуск
Владелец сервиса выдаёт организатору семьи пилотный допуск по Telegram ID. При открытии бота / Mini App сервер проверяет личность, затем показывает краткое описание хранения и доступ к политике. Не запрашивать телефон, адрес, контакты и доступ ко всей галерее.

Организатор создаёт семью: название по умолчанию «Наша семья», имя ребёнка обязательно 1–60 символов, дата рождения необязательна и не в будущем. Аватар ребёнка — нейтральный круг с первой буквой; специальную загрузку аватара в MVP не делать. Часовой пояс предлагается из устройства; владелец подтверждает его. Для Bot-only создания открывается Mini App, а не многошаговая анкета в чате.

Приглашение: владелец выбирает `Просмотр` (по умолчанию) или `Полный доступ`, создаёт одноразовую ссылку на 72 часа и отправляет конкретному близкому. Открытие ссылки показывает название семьи, выдаваемые права и кнопку «Присоединиться». До подтверждения участие не создаётся. Приглашение можно отменить. Повторное подтверждение тем же пользователем идемпотентно; другой пользователь получает «Приглашение уже использовано».

Уже состоящего в другой семье человека не переносить автоматически. В MVP показать ограничение одной активной семьи. На уровне модели membership остаётся отдельной сущностью; ограничение вынести в политику пилота.

## 5. Автопубликация из личного бота
Обычный текст публикуется как заметка. Фото / видео с Telegram-caption получает ту же подпись. Голос публикуется без расшифровки. После надёжного сохранения бот присылает «Сохранено в семейную ленту» и кнопки «Открыть», «Добавить подпись» (для медиа).

Никакого обязательного подтверждения перед каждой записью нет. При первом использовании сообщить: «Всё, что вы отправите сюда, появится в ленте вашей семьи». Ошибки и служебные команды не публикуются. В группах бот не принимает содержимое и не запрашивает админские права.

## 6. Подпись к голосу и другим медиа
Два явных пути: текстовый ответ на исходное медиа-сообщение; либо кнопка «Добавить подпись» у подтверждения бота и ответ на созданный им запрос. Оба меняют `Memory.body` конкретной записи. Следующее обычное сообщение без связи — отдельная заметка, а не подпись к последнему файлу.

Кнопка «Изменить подпись» явно сообщает, что новый текст заменит прежний. Подпись можно редактировать и удалять в Mini App. Реальные разговоры под записью не реализуются.

## 7. Лента
Последние моменты сверху, группировка «Сегодня», «Вчера», иначе дата. Один линейный список; нет рейтинга популярности. Сортировка по `occurred_at DESC, id DESC`, а не по лайкам или времени редактирования. Публикация не прыгает наверх после правки подписи. Дату можно исправить в редакторе. Будущие моменты запрещены; небольшая погрешность часов до пяти минут допускается сервером.

Фильтры: «Все», «Фото», «Видео», «Голос», «Заметки». Это фильтрация одной ленты, не пять разделов. Поиска по словам в MVP нет: не рисовать лупу, ведущую в пустоту. Постраничная загрузка по 20 записей, без пропусков и дублей. При новых записях во время чтения старых показывать «Есть новые воспоминания»; не сбрасывать позицию без действия пользователя.

Лайк один на пользователя и запись. Повторное нажатие снимает его. Лайк не уведомляет всю семью, не открывает список популярного и не создаёт социальной статистики. При отзыве членства лайк скрывается из счётчика; выдавать счётчик только активных участников.

## 8. Добавление из Mini App
Единственная кнопка «Добавить» в нижней панели. Она открывает варианты «Фото или видео», «Заметка», «Голосовое в боте». Фото/видео выбираются системным выбором файла и загружаются в наше хранилище; это необходимо в том числе для роликов больше лимита облачного Bot API. Заметка создаётся простой формой. Запись с микрофона внутри WebView не делается: голос записывается привычным способом в боте, затем появляется в ленте.

В режиме просмотра центр панели не является неработающей кнопкой: отображается текстовая метка «Просмотр», а добавление не показывается. На прямой запрещённый API-запрос — 403.

## 8.1. Воспроизведение видео и голосовых в Mini App
В самом чате Telegram фото, видео и голосовые открываются средствами Telegram. Внутри Mini App нативный Telegram-плеер не является частью нашего HTML-интерфейса, поэтому воспроизведение строится на стандартных HTML5 Media APIs. **Не разрабатывать собственный decoder, buffering engine или media state machine.** Движок — браузерные `<video>` и `<audio>` / `HTMLMediaElement`; наша зона ответственности — тонкая React-оболочка, права доступа, состояние UI и дизайн.

Видео: poster в карточке; ручной Play/Pause; seek/progress; текущее/общее время; fullscreen; `playsInline`; без autoplay. До запуска использовать `preload="none"` либо `metadata`, не выкачивать ролик целиком ради ленты. На поддерживаемых WebView рисовать собственные контролы поверх HTML5 video; если проверка реального клиента показывает несовместимость custom controls, разрешён безопасный fallback на native `controls` без отдельного медиадвижка. Громкость в MVP оставляется системному устройству.

Голос: `<audio>` является скрытым/минимальным движком, а в карточке показывается наш компактный компонент: Play/Pause 44×44, waveform из измеренных peaks, длительность и необязательная подпись под полосой. По waveform можно перейти к позиции; если peaks отсутствуют или устройство не поддерживает нужное взаимодействие, использовать обычный progress slider. Никакой расшифровки, AI, редактора звука или ускорения речи в MVP.

Одновременно воспроизводится только один audio/video. Запуск второго ставит первый на паузу; скрытие Mini App, отзыв доступа или выход из detail останавливает воспроизведение. Приватный backend отдаёт playback через авторизованный путь с Range/206, чтобы перемотка не требовала скачивать весь файл. Нельзя добавлять тяжёлую media-player библиотеку только ради кнопок: новый dependency допустим лишь после воспроизводимого blocker на целевых Telegram iOS/Android и отдельного ревью.

## 9. Редактирование, удаление и выход
Редактируются подпись/текст и дата. Замена файла внутри записи не входит в MVP: удалить запись и создать новую. Удаление требует подтверждения, немедленно скрывает запись от семьи и ставит удаление объектов в надёжную очередь. Удаление исходного Telegram-сообщения не считается удалением из приложения. Пользователь видит об этом короткое пояснение.

Участник может выйти из семьи; владелец не может выйти, оставив семью без владельца. После выхода сервер отказывает в новых чтениях и выдаче файлов. «Закрыть Mini App» не означает выйти из семьи или удалить аккаунт.

## 10. Необходимая эксплуатация, но не новые пользовательские функции
Резервирование, восстановление на тестовом окружении, безопасное удаление, журнал ошибок без содержимого, базовый экспорт ZIP по запросу владельца. Для пилота экспорт и удаление всей семьи допускаются через поддержку: без отдельного большого кабинета, но с рабочими операционными командами. Человек не должен платить или просить Telegram-пароль, чтобы получить свои данные.
