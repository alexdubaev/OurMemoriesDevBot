# Порядок и параллельная работа
Номера блоков сохраняют старые имена файлов; номер не всегда означает очередность. Нормативный порядок — `task-plan.json` и лист «План» в Excel.

`00 → 01 → 02 → (03 ‖ 06) → контроль A → 04 → (05 ‖ 08) → контроль B → 07 → 09 → 10 → 11`.

## Волна A — голубая заливка
Запускать только после принятого и слитого блока 02. Два агента начинают от одного base SHA.
- 03, Sol: backend media/storage, квота, загрузки, защищённая выдача. Не меняет UI, CSS, компоненты и frontend assets.
- 06, Luna: frontend design-system, карточки-каркасы, навигация, raster WebpIcon. Не меняет auth, HostBridge implementation, API-контракты, БД, backend, lockfile.
Компоненты 06 получают role/insets/capabilities через зафиксированные props. Development fixtures не выдают себя за live API. Интерфейс HostBridge уже задаёт 01; менять его может только интегратор.
Контроль A: последовательное squash обоих PR, обновление второй ветки после первого merge, проверка contracts/typecheck/архитектуры и smoke оболочки. Оба PR зелёные по отдельности недостаточны.

## Волна B — зелёная заливка
Запускать после 04 и контроля A.
- 05, Terra: media transcoding, Telegram caption flow, backend jobs. Не меняет frontend.
- 08, Terra: onboarding/invites/family UI. Использует API 01 и визуальные компоненты 06. Не меняет backend, contracts, schema, CI и assets 06.
Прежняя зависимость 08 от 07 снята: семейный интерфейс не зависит от карточек живой ленты. Навигация и mock-адаптеры из 06 уже доступны. Если обнаружится реальная общая зависимость — сначала интегратор фиксирует интерфейс, волна блокируется до этого.
Контроль B: последовательное принятие, проверка актуального main, интеграционный тест семейных прав и целевые media-tests. Затем 07 интегрирует всю ленту.

## Общие файлы
Одновременно один владелец: manifests и lockfile, Prisma schema/migrations, contracts, root composition, routes/generated tree, CI, global config. Агент предлагает точный patch интегратору, а не «заодно правит» общий файл. Для новой зависимости отдельное решение перед параллельным запуском. Исключение — технический владелец контракта в текущем последовательном блоке по письменному назначению.

## Что отдавать каждому агенту
Task ID, модель, base SHA, своё имя ветки и рабочая папка, allowlist, forbidden paths, перечень потребляемых интерфейсов, ссылки на 2–5 нужных экранов, критерии приёмки. Пример задания см. `../../templates/AGENT_DISPATCH.md`.

## Что не параллелить
01 с 02/03; 03 с 04; 04 с 05; 07 с 09; destructive privacy и релиз с незавершёнными изменениями. Параллельные разные тесты не должны использовать одну тестовую БД/порт. Полный suite всех агентов на каждом коммите не нужен.
