# Брендбук · Наши воспоминания
**Версия 1.0 · 9 сентября 2026 · визуальное направление №1 «Классическая лента».**

Этот документ сохраняет визуальную и редакционную последовательность будущих изменений. Он не расширяет состав MVP. Технические размеры и состояния находятся в `design.md`; машинные значения — в `design/tokens.json`.

## 1. Суть бренда
Небольшие моменты семейной жизни заслуживают спокойного места, где их можно сохранить и снова увидеть. Не социальная сеть, не медицинский дневник, не соревнование родителей и не инструмент оценки ребёнка.

Рабочая формулировка: **«То, что хочется помнить».** Объяснение продукта: «Отправляйте фотографии, видео, голосовые и заметки — они появятся в ленте вашей семьи». В MVP не использовать формулировки про автоматическое понимание, интеллект, распознавание и «семейную память, которую вообще не нужно заполнять»: пользователь всё-таки сам отправляет материалы.

Название «Наши воспоминания» — временное описательное имя, пригодное для прототипа. Регистрационная доступность не проверялась. Позднее смена имени производится через продуктовую конфигурацию, не через тысячи строк кода. Отдельный нарисованный логотип этим пакетом не утверждён.

## 2. Кому говорим
Главный пользователь — взрослый, желающий сохранить момент ребёнка; второй — близкий родственник, которому важно просто открыть и посмотреть. Интерфейс должен быть понятен бабушке, а не только человеку, знакомому с современными приложениями.

Не предполагать, что данные добавляет только мама или что в каждой семье два родителя. Участники называются выбранными ими именами; «мама/папа/бабушка» не обязательные роли и не права доступа. Дети не получают собственные аккаунты в этом MVP.

## 3. Характер
**Тёплый, спокойный, точный, личный.** Тепло создают фон, мягкие углы, фотографии и человеческий язык. Точность создают понятные статусы сохранения, аккуратные даты и честные предупреждения. Не смешивать «уют» с детсадовским оформлением.

| Нужно | Не нужно |
|---|---|
| Светлый фон, реальные семейные материалы | Радуга, игрушечные 3D-иконки, конфетный градиент |
| Спокойная карточка с одной историей | Социальная механика популярности и лента рекомендаций |
| «Сохранено в семейную ленту» | «Ваш бесценный момент навечно защищён!» |
| Ошибка + понятное действие | Упрёк пользователю или тревожный маркетинг |
| Автор и дата мелко, но читаемо | Декоративные числа/подписи размером 9 px |

## 4. Обещания и доверие
Допустимо: «Доступ по приглашению», «Видно участникам вашей семьи», «Оригинал сохранён» — только после фактического подтверждения original_status. Недопустимо без реализации/оснований: «Хранение навсегда», «Никто кроме вас технически не может увидеть», «Сквозное шифрование», «Telegram гарантирует сохранность».

«Приватно» означает ограничение доступа нашим сервером, не запрет скриншотов родственникам. Приглашение обязано явно показывать выдаваемые права. Согласия не скрываются внутри декоративной кнопки. Не использовать чужие фото детей в рекламных материалах без подходящих прав и согласия.

## 5. Визуальный принцип
Из выбранного макета сохраняем один светлый поток карточек, широкие фотографии, отдельные аудиокарточки, даты и мягкий коралловый акцент. Не переносим сгенерированные лишние элементы: календарь, события, общую галерею, меню «Ещё», два разных плюса и случайные счётчики.

Нормативный MVP: сверху заголовок/ребёнок, затем фильтры и лента; снизу «Лента / Добавить / Семья». Полоса Telegram и системный status bar остаются настоящими, не рисуются внутри страницы.

| accent-soft | #F4A4AE | Большой плюс, декоративная подложка |
| accent-strong | #A83750 | Лайк, фокус, активное состояние, акцентный текст |
| accent-tint | #FBE9ED | Мягкий фон selected chip/голоса |
| success | #276749 | Успешное действие, только вместе с текстом |
| danger | #B4233A | Удаление, ошибка |
| overlay | rgba(35,28,33,.40) | Модальный фон |

Пропорции ориентировочные: 80% светлых нейтральных поверхностей, 15% контента, до5% брендового акцента вне фотографий. Не раскрашивать каждый тип записи отдельным ярким цветом. Семейные фото не перекрашиваются под палитру.

Белая маленькая надпись на accent-soft запрещена: контраст недостаточен. На мягком коралле — text; на accent-strong — white. Для меток брать text-muted, не прозрачность30%. Контраст проверять численно; обычный текст минимум4,5:1, значимые элементы3:1. Минимальная цель клика44×44 — наше более строгое правило удобства. [A1]

## 7. Типографика
Основной шрифт интерфейса: **Inter**, начертания400/500/600/700, с кириллицей. Он близок к нейтральной чёткой типографике выбранного макета. Резерв: system-ui, -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif. Агент проверяет лицензию и загружает нужный шрифт из официального источника при реализации; файлы шрифта не входят в этот комплект.

| Стиль | Размер / интерлиньяж | Вес |
|---|---|---:|
| Заголовок экрана | 20 / 28 px | 600 |
| Имя ребёнка | 16 / 22 px | 600 |
| Заголовок группы дат | 15 / 22 px | 600 |
| Основной текст | 16 / 24 px | 400 |
| Подпись карточки | 15 / 22 px | 400 |
| Метаданные | 12 / 18 px | 400 |
| Кнопка | 15 / 20 px | 600 |
| Нижняя навигация | 11 / 16 px | 500 |

Нельзя превращать подписи в картинку. Межбуквенный интервал0, капс только для технических меток документа, не в основных кнопках. Не использовать рукописный шрифт для чтения заметок. В длинном тексте сохранять переносы пользователя; не выравнивать по ширине.

## 8. Рабочее написание названия
На главном экране текстовый wordmark «Наши воспоминания», Inter Semibold20. Без самолётика Telegram, без имитации verified badge, без короны. Защитное поле не меньше высоты строчной буквы с каждой стороны в отдельном рекламном макете. В тесной навигации не ужимать имя до12px: можно показывать «Воспоминания» через заранее утверждённую compact-label.

Будущий знак должен работать в24px, в одном цвете и не повторять значок Telegram. Новую пиктограмму нельзя автоматически объявлять финальным товарным знаком.

## 9. Иконки — обновление 2.2
Собственный согласованный растровый набор WebP с реальной прозрачностью. Базовый рисунок 24 CSS px, экспорт 48 и 72 px для плотных экранов; зона нажатия минимум44×44. Цвета text-muted и accent-strong, белые варианты только для тёмного viewer. Одинаковая оптическая толщина и скругление линий.
Не использовать SVG, SVG data URI, icon fonts, Lucide/Hugeicons components для новой графики. При использовании shadcn/PhotoSwipe переопределять их визуальные icon slots нашими WebP, не ломая доступность библиотек. Системные controls браузерного видео остаются системными.
Сердечко outline→filled — лайк, не избранное. Графика без подписи получает доступное имя на управляющей кнопке. `img` внутри имеет пустой alt, если имя уже у кнопки. Пользовательские emoji не заменяются.
См. `ASSET_GUIDE.md` и корневой `assets/manifest.json`. Значки — переиспользуемые ресурсы, а не генерация во время работы приложения.

## 10. Фотография и видео
Картинка — главный эмоциональный элемент. Предпочтительны натуральные цвета и дневной свет; приложение не добавляет фильтры, skin smoothing и AI-обработку. Не обрезать исходник навсегда. В ленте можно использовать center crop, а в полноэкранном просмотре виден целиком.

Разрешённые demo-материалы — явно синтетические fixtures или разрешённые семейные samples. Ребёнок на исходном AI-макете — визуальный пример, не реальная личность пользователя и не фотография для рекламы продукта. Не записывать «Варя» как настоящее имя дочери владельца.

## 11. Компоненты как часть бренда
Карточка белая, radius16, слабая тень, аккуратные metadata. Никакого стекла, параллакса и массивной анимации. Внутренние отступы14px, внешний gutter16px. В нижней панели один главный плюс, не второй плавающий поверх фото.

Голосовая карточка: круг play44px, настоящая waveform или progress bar, duration, подпись ниже. Пустой голос не подменять распознанным текстом. Видео: play overlay и duration; autoplay off. Заметка — полноценная карточка, а не подпись к несуществующему изображению.

## 12. Голос интерфейса
Обращение на «вы», без официоза и уменьшительно-ласкательных слов. Кнопки — действие: «Сохранить», «Пригласить», «Добавить подпись», «Повторить». Не «ОК» там, где можно назвать результат.

| Ситуация | Текст |
|---|---|
| Пустая семья | «Здесь появятся ваши воспоминания» |
| Помощь | «Отправьте боту фото, видео, голосовое или заметку» |
| Успех | «Сохранено в семейную ленту» |
| Pending | «Сохраняем файл…» |
| Голос processing | «Голос сохранён. Готовим воспроизведение» |
| Ошибка | «Не удалось сохранить файл. Попробуйте ещё раз» |
| Viewer | «Вы можете смотреть воспоминания и ставить сердечки» |
| Invite full | «Можно добавлять, изменять и удалять записи семьи» |
| Отзыв доступа | «Доступ к этой семье закрыт» |

Не писать «потеряно навсегда» при временной ошибке, «успешно обработано» при наличии только file_id, «бабушка ничего не понимает». Emoji в служебном UI использовать редко; emoji автора в заметке сохраняются.

## 13. Анимации, звук, доступность
Transition160–220ms, fade/малое смещение; reduced-motion выключает движение. Никаких пульсирующих сердец, конфетти при лайке и звукового автозапуска. Audio/video начинают играть только по действию человека, одновременно один player. Не отнимать прокрутку ленты сложными жестами.

VoiceOver/TalkBack: порядок header→filters→date→cards→nav; кнопка play описывает запись, likes aria-pressed, error aria-live. Формы имеют подписи, не только placeholders. Увеличение текста до200% не скрывает важные действия. Disabled не единственный способ объяснить запрет.

## 14. Правила дальнейших изменений
Изменения контента/подписей не меняют компонентную структуру. Изменение палитры — только токенами, с повторной contrast-проверкой. Новый компонент сперва получает состояния/loading/error/a11y, потом используется. Новые платформы не меняют семантику family/memory.

Визуальный review должен ответить: соответствует ли светлой классической ленте, не появилась ли лишняя навигация, остался ли один главный путь добавления, читаемы ли метаданные, не сделаны ли неподтверждённые обещания. Существенная смена типографики, палитры, характера карточек или количества разделов требует отдельного решения владельца.

## 15. Хранение дизайн-решений
`design/tokens.json` → `tokens.css`; `ui-copy.ru.json`; `design.md`; reference выбранного варианта; screenshot-базис на fixture. В `DESIGN_CHANGELOG.md` фиксировать дату, мотив изменения, затронутые компоненты и кто согласовал. Ни один агент не обновляет golden screenshots, только чтобы спрятать случайное отклонение.
