# memoLy Control — визуальный контракт shadcn/ui (редакция 2)

## Принято владельцем

Источник: исправленный интерактивный HTML `memoly-control-shadcn-fixed.html` от 22.10.2026; старый зелёный дизайн rejected. Профессиональная нейтральная админка в светлой и тёмной темах, тонкие границы, компактные данные, ровная типографика, небольшие радиусы. **Это не форк всего satnaing/shadcn-admin**, а составленные из shadcn/ui компоненты существующего React/Vite стека memoLy.

## Шесть экранов

1. **Обзор:** горизонтальная полоса из четырёх KPI (Уникальные пользователи, Активные семьи, Активные за период, Учтено у семей), график регистрации/наблюдаемой активности (7/30/90 дней), таблица последних семей, состояния подключений/хранилища. «Активные» не означает «онлайн», «Учтено у семей» не означает физическое место на диске.
2. **Семьи:** полноценная таблица с поиском, фильтром status/MAX, сортировкой, курсорной пагинацией, ответами loading/empty/error; клик в строку открывает правый Sheet с метаданными, участниками, учётом storage и последним проверенным состоянием MAX.
3. **Пользователи:** одна строка на User.id, число разных семей, дата регистрации, отдельные факты сессии и активности. Клик открывает участника в Sheet с членствами и контекстом каждой семьи; нет единой «семейной роли» пользователя.
4. **Хранилище:** раздельные family quota, реальный объектный storage, серверная файловая система, PostgreSQL, backups. Карточки с источником и временем измерения; status/stale/coverage, а не фиктивная ёмкость 500GB. Структура ресурсов и диаграммы не суммируют вложенные объёмы.
5. **Подключения:** конфигурированные источники product_db, media_storage, host, PostgreSQL, MAX binding, health/release evidence; только состояние, тип, последний успех, lastAttempt, ошибка из фиксированного allowlist. Нет редактирования URL провайдера браузером.
6. **Состояние системы:** backend live/ready, static, worker/scheduler evidence, DB connectivity, очереди, deployment/backup evidence; HTTP 200 не доказывает работу worker и MAX.

## Навигация и интерактивность

Слева Sidebar со списком разделов; справа Breadcrumb, общий поиск по кнопке/Ctrl/Cmd+K, обновление, переключатель темы. На телефоне Sidebar заменён на Sheet. Таблица не заставляет горизонтально прокручивать всю страницу; допустим скролл только внутри таблицы или адаптация колонок.

Строка семьи -> Sheet -> участник -> детальная карточка -> возврат с сохранением фильтров/scroll. Search debounce ~300ms, серверные результаты, отмена старых запросов, ограниченная выдача. Серверные фильтры/сортировка/курсоры; UI никогда не имитирует страницу 173 при отсутствии возможности перейти по ней. CSV — реальный защищённый export, а не браузерная выгрузка сырых данных.

График — Recharts и доступная текстовая/табличная альтернатива. Светлая/тёмная тема scoped к `.memoly-control-root` и порталам Dialog/Sheet, не перекрашивает family UI v4. Button/Card/Table/Badge/Input/Select/Dialog/Sheet/Skeleton/Empty/Command брать из уже установленной библиотеки, предварительно проверив Base/Radix API. Новые иконки по WebP-правилам AGENTS.md, не копировать декоративный inline SVG из demo.

## Разница demo и production

**Не переносить** React18/vendor bundle, самодельные helpers, inline preview navigation/React fallback, синтетические пользователи/семьи, переключатель mock-провайдера, имитацию устаревания данных. Не делать большой «init shadcn» с перезаписью семейного UI. Точные API/счётчики определены SPEC/DATA_MAP, не подписями демонстрации.

Без JavaScript / при загрузочной ошибке показать пустую безопасную оболочку и повтор, **не белый экран**. Не включать реальные данные в HTML, offline cache, preview/скриншоты и JS hydration; только после успешного owner API guard. Отдельно обработать logout/401/403/BFCache и убрать private query cache.

Визуальная проверка: 1440, 768, 390, 320 CSS px, оба режима темы, таблицы, Sheet, Command, error/stale/empty/loading, keyboard и safe areas. Desktop WebKit не является физическим iPhone/MAX.
