# Стартовый промпт для Codex

Ты продолжаешь существующий memoLy и выполняешь задачу **MEMOLY-CONTROL**:
создать отдельную закрытую веб-панель владельца сервиса на основе подготовленного дизайна
и реальных данных проекта. Это не раздел семейного приложения.

Пакет: docs/mvp/owner-dashboard/.
Ветка публикации пакета: docs/memoly-control-handoff-20261022.
Исследованный source: 0dbc4c486f3a7841ae2d72d7fc617e552d502941; не считай его текущим автоматически.

Сначала прочитай корневой AGENTS.md, .agents/skills/teamlead-development/SKILL.md,
docs/DEPLOYMENT.md и deploy/selectel/README.md. Получи свежий origin/main,
проверь рабочий каталог, чужие изменения/worktrees и фактический production SHA.

Если пакет ещё не в main, найди его PR по указанной ветке. Прочитай его через git show/API,
выполни необходимое независимое техническое review docs-пакета и штатно интегрируй PR,
если gates выполнены. Не копируй файлы из чата и не заменяй свежий main старым архивом.
Отдельный production deploy только ради docs/reference не нужен.

Прочитай README.md, SPEC.md, DATA_MAP.md и PLAN.md. Восстанови byte-exact HTML:
node docs/mvp/owner-dashboard/reference/restore-reference.mjs
Открой .scratch/memoly-control-reference/memoly-owner-dashboard-demo.html как визуальный эталон.

Реализуй шесть разделов, отдельный /control/ entry, owner-only API и серверные адаптеры.
Повторно используй MAX browser-link авторизацию. Владелец одной семьи не получает доступ
ко всем семьям; access определяется точным server allowlist. Не вводи password admin,
не меняй User.role, ACL семей и принятый UI v4. Никаких реальных данных/токенов в Git.

Считать отдельно аккаунты, членства, сессии и приглашения. Логическая квота семьи,
реальные storage bytes, диск хоста и размер БД — разные величины. Не приписывай внешним
MAX-видео выдуманные байты. Пустое/неизвестное/устаревшее измерение не становится нулём.
Активность и историю, которых раньше не было, начни собирать минимально и показывай coverage;
не называй действительные сессии людьми онлайн. Demo values в рабочей версии запрещены.

Работай по трём этапам PLAN.md самостоятельно, в собственной task-ветке/worktree и с
изолированными тестовыми ресурсами. Сохрани дизайн, но не копируй static HTML/innerHTML/SVG
как production architecture. Не делай новый глобальный аудит и не добавляй SaaS на будущее.

Задача разрешает необходимую ограниченную read-only access boundary, аддитивные telemetry
models/migrations и точную release/recovery аттестацию при доказанной совместимости.
Не ослабляй security/release guards. Обычные PR, squash merge и штатный production deploy
доведи до конца по постоянным разрешениям владельца. Одно независимое review,
ограниченное исправление существенных замечаний, обязательный FULL на итоговом SHA,
guarded release, smoke и recovery-readiness. Не останавливайся на MERGED.

Если отсутствует проверенный owner UUID, штатный production доступ или credential источника,
исследуй доступное и запроси только конкретное недостающее разрешение/подтверждение безопасным
способом. Не проси присылать секреты в чат. Не выдавай неподключённый источник за успешный.

Финал: адрес панели, main/runtime SHA, PR, проверки, реально подключённые источники,
отсутствующая история/конкретные ограничения. Никаких заявлений о физическом iPhone,
реальном storage или production, если эти проверки не выполнялись.
