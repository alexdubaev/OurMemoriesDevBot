# Telegram: приём, автопубликация и подписи

## T00. Development-бот
Для разработки и закрытого пилота уже создан `@OurMemoriesDevBot` с отображаемым именем «Наши воспоминания • Test». Не создавать новый development-бот. Публичный username фиксируется в Git, token — только в server-side secret environment. При старте `getMe` обязан подтвердить ожидаемый username и вернуть фактический numeric bot_id; mismatch → fail-fast. Подробный контракт: [TELEGRAM_BOT_SETUP.md](TELEGRAM_BOT_SETUP.md).
## T01. Граница платформы
Только личный чат с ботом. В группе контент не сохранять; сервисное объяснение без чтения/анализа переписки. Mini App узнаёт пользователя через проверенные сервером initData и свою сессию. Бот по Telegram ID ищет ExternalIdentity, membership и право full. Viewer не публикует даже прямой отправкой файла.

## T02. Durable inbox
Webhook проверяет secret-token header и ограничение размера. После durable записи update с unique(bot_id,update_id) вернуть200, тяжёлую работу выполнить worker. Повтор не создаёт новую запись. Данные для подписи/источника хранятся отдельно от публичного DTO. Сообщение создаёт одну логическую запись; permanent source uniqueness не зависит от срока outbox dedupe.

## T03. Фотоальбом
Ключ album=(bot_id,chat_id,media_group_id). Собирать в PostgreSQL, не только в памяти процесса. Окно тишины2с после последнего принятого элемента, общий предел10с от первого; при перезапуске продолжать из БД. Atomic claim защищает от двух workers. Поздний элемент добавлять к существующему фотоальбому транзакционно, без второй карточки, пока общее количество≤10. Порядок по message_id. При смешанном альбоме каждый элемент становится отдельной записью; групповой итог сообщает фактическое количество. Не заявлять конец доставки по несуществующему Telegram album-end event. Тестировать поздний элемент и изменение группы из photo-only в mixed до публикации; если mixed выявлен после публикации, зафиксировать отказ позднего элемента с объяснением, не молча менять опубликованную семантику.

## T04. Сохранение
Текст не-команда без reply → note. Photo/video caption → body. Voice сохраняется исходным файлом; AI/транскрипции нет. Разрешённые форматы и лимиты — 05_STORAGE_SECURITY. Импорт файла → проверка → stored original → публикация. Производная может быть pending, и интерфейс показывает это честно. Ошибка исходного файла не считается опубликованной записью.
Большие файлы, которые облачный Bot API не позволяет получить, отправляются пользователем через Mini App. Никакого серверного Bot API self-hosting, чтения user-account истории или обхода лимитов в MVP.

## T05. Подпись
Нажатие «Добавить подпись» создаёт CaptionRequest с family/user/memory/version, сроком30мин и конкретным prompt_message_id. Принимать только текстовый reply соответствующего пользователя в том же личном чате. Повтор consumed reply идемпотентен. Ответ на исходное медиа с известным source mapping тоже может обновить body. Обычный следующий текст без reply всегда отдельная note.
Права full проверяются заново; удалённая запись/отозванный участник/expired prompt → отказ без новой note. Конкурентное изменение body →409-подобное объяснение и новый запрос, не тихое overwrite. Подпись заменяется целиком, не появляется обсуждение. ForceReply отмена /cancel не публикует note.

## T06. Сообщения и команды
/start: описание, предупреждение об автопубликации, «Открыть ленту» либо приглашение/онбординг. /help: четыре формата, подпись, большие видео, удаление. /cancel: отмена текущего запроса подписи. /privacy: политика. Команды, кнопки и служебные ответы не превращаются в воспоминания.
После stored: «Сохранено в семейную ленту», «Открыть», «Добавить подпись». Для voice/video rendition pending: «Оригинал сохранён. Готовим воспроизведение». Очередь/ошибка не маскируется фразой «готово».

## T07. Изменения источника
Редактирование/удаление исходного сообщения Telegram не является общей синхронизацией и не должно удалять семейный архив. Для исправления — явная подпись или редактор Mini App. File IDs и токен бота не выдаются в client DTO. Удаление приложения отдельно от удаления чата объяснить в /help.

## T08. Проверки
Duplicate update; restart before/after commit; timeout download; viewer send; revoke while import; late photo; album concurrency; empty caption; reply foreign source; expired prompt; several memories parallel; interrupted rendition; forbidden group. Для лайков и приглашений bot callback_data — opaque action ID, не доверенный family/role.
