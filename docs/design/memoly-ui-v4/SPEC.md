# SPEC — memoLy UI v4

**Задание:** `MEMOLY-UI-V4-PIXEL-IMPLEMENTATION`.
**Результат:** перенести оформление v4 на реальные существующие экраны memoLy. Не разрабатывать альтернативный дизайн. Все значения ниже — CSS px, не физические пиксели экрана.

## 1. Границы

Поддерживаются только MAX, MAX Mini App и Web/PWA с MAX authentication. Текущие серверные API, роли, загрузка и публикация воспоминаний, приглашения, MAX channel binding, browser-link, F12, даты источников, idempotency, unread и private media остаются прежними.

Разрешённая новая логика — только вычисление визуальной рамки медиа и композиция UI из существующих данных/handlers. Нельзя менять семейную ACL, Prisma/schema/migrations, серверные контракты, provider lookup, downloader/transcoding, Service Worker, ключи кэша, загрузку авторских аватаров, media engine или алгоритм обработки очередей.

Поздние исправления caption/date MAX из свежего main сохраняются. Не возвращаться к старому SHA из прототипа. Не заменять корректную дату источника датой пересылки ради совпадения скриншота.

## 2. Эталон и точность

Визуальный источник — **v4**, не v1/v2/v3, не изображения-концепты с придуманными комментариями. Публичный `reference.zip` содержит автономный HTML и CSS. В нём только медиа/имена обезличены; иллюстрация шапки, структура и геометрия сохранены.

Канонический viewport: **390×844**, DPR=1, safe insets=0, zoom=100%. Проверять также 320×844, 430×932, desktop 1280×900. Не добавлять нарисованный status bar, время, батарею, рамку телефона и подпись автора макета в настоящее приложение.

Для одного браузера/шрифта: размеры шрифтов, line-height, spacing tokens — точные; отклонение rect позиции/размера не более **1 CSS px**, кроме явно перечисленных accessibility-поправок. На другом OS нельзя требовать одинакового сглаживания букв: сравнивать геометрию, вычисленные стили и переносы на одинаковой среде. Не выдавать визуальный процент сходства без выполненного сравнения.

На длинном имени, увеличенном тексте и системном масштабе фиксированные размеры являются минимальными: контент растёт, не обрезается. Доступность и данные важнее искусственного совпадения bitmap.

Использовать существующий scroll owner и нормализованные host insets. Не добавлять одновременно host top inset и такой же CSS safe-area повторно. Шапка начинается сразу после системной/host safe area. **Дополнительный margin/padding над ней = 0.** Не задавать padding-top, изображающий status bar. При 0 inset её y=0.

## 6. Пропорции медиа: только визуальная функция

Переход от общего 4:5 ко всем публикациям к v4 должен быть явным и тестируемым. Рамка вычисляется **один раз на актуальную публикацию по metadata**, не по активному слайду и не через скачивание файлов.

1. Одиночное фото/видео с валидными display width/height: ratio = clamp(width/height, **0.8**, **2.4**).
2. Альбом только фото: ratio первого вложения в исходном порядке, тот же clamp. Если его metadata нет — **0.8**.
3. Несколько вложений, среди которых есть видео: **0.8 (4:5)**.
4. Нет валидного размера / pending poster: **0.8**. Не менять уже показанную рамку от `loadedmetadata`, poster readiness, смены слайда или загрузки другого изображения. При настоящем изменении состава записи пересчитать в рамках её обычного обновления.
5. Повторное открытие сохраняет индекс согласно существующей логике. UI calculation не хранить в БД, localStorage или бесконечном Map по всей ленте; не вводить новый media cache.
6. Полноэкранный viewer использует доступную высоту viewport и contain, не ограничивается ratio карточки.

Для canonical fixture: city album **1.655914** → height **216.1875** при width358; river **2.183099**; autumn **0.8**; kitchen **0.945148**; mixed **0.8**; square-like video **1.097674**; sea **1.444444**; garden **1**. Это значения метаданных тестовых изображений, не жёстко зашитые пропорции по ID или названию.

Слайды: width100%, один слайд за раз, порядок неизменен. Предыдущий/следующий не выходит за границы, loop false. Использовать действующие Embla/PhotoSwipe/MixedMediaViewer; не заменять их CSS `:target`/scroll engine из демо.

Счётчик: top/right **9**, padding **4 8**, radius **13**, bg `#14201894`, text **10/14**. Для одной фотографии не показывать счётчик и точки.

Точки: visual dot **4×4**, active **13×4** с radius5, inactive `#c6d0c2`, active `#71917a`; исходная строка19px, hit width25px. Production patch: hit **24px** в высоту, min24 по ширине, row24px; это +5px под альбомом. Активная точка обновляется настоящим selectedIndex, не CSS hash. При большом числе вложений не создавать горизонтальный overflow всей страницы.

| Long caption | Переносы и текст доступны полностью существующим способом; не молчаливая обрезка данных |
| Viewer role | Просмотр и реакции; скрытые write-контролы не заменяют серверные проверки |
| Full non-owner | Разрешённые загрузки/приглашения, без owner-management |
| Invite draft/pending | Реальная форма роли/имени; pending защищён от повторного submit и Back как раньше |
| Invite committed/read failed | Ссылка сохраняется, warning и retry только чтения; новая ссылка не создаётся |
| Expired/revoked/used invite | Существующий безопасный отказ + «Мои семьи», без повторного accept |
| Role updated | Свежая роль/version отражаются без reload, epoch-семантика прежняя |
| Family save/read failed | Успешное сохранение не выдаётся за failed mutation; read retry прежний |
| Family A → B | Старый ответ A не меняет выбранную B; query keys/selectionVersion неизменны |
| Access revoked/logout | Прежняя очистка scope и отказ API, не скрытие сообщения ошибки поверх доступных данных |
| Channel disconnected/error | Реальный статус и существующее разрешённое действие; binding не изменять для визуального теста |
| Add/photo/video/note/voice | Существующие composers и прогресс/ошибки; общая оболочка v4, не demo-заглушки |
| Child/member profile, crop, invitations list, leave/delete confirmations | Существующие поля, permissions и navigation; tokens/row/sheet primitives этого раздела |
| Settings | Сохранить реальные настройки и темы; НЕ добавлять demo-toggle «Все 4:5»/«Чуть плотнее» и пояснения макета |
| All families | Сохранить реальный hub и порядок/семейные роли, tokens v4; одинаковые названия не объединять |

Новые comments, search, calendar, stats, export или другие product features не входят в задачу. Не делать второй UI-router.

## 11. Обязательные точечные accessibility-поправки

Это **исчерпывающий список** допустимых отличий от сырого HTML-эталона, а не творческая свобода:

1. Вторичные текстовые цвета, которые в прототипе слишком светлы для малого кегля, заменить на семантический AA secondary: базовый `#596858`. Даты остаются12px, время11px, роли10px; их не уменьшать и не компенсировать контраст ростом шрифта. Проверять минимум4.5:1 для обычного текста на фактической подложке, включая иллюстрацию. Другие темы — эквивалентный проверенный контраст.
2. Основные icon-only controls имеют hit44×44 без увеличения видимого glyph; author row44 вместо43. Pagination hit24 вместо19 по высоте (+5px строке). Не создавать перекрывающиеся hit rectangles поверх соседнего медиа.
3. При масштабировании текста до200%, длинных именах и узком viewport containers растут. Нет `user-scalable=no`, `maximum-scale=1`, глобального запрета selection или text-size-adjust:none. В нормальном состоянии размеры из таблиц обязательны.
4. Native buttons/links, корректные aria-label/aria-pressed/aria-current, focus trap и восстановление focus в существующем Dialog. Escape/host Back закрывает верхний слой по прежним правилам. Семантика disabled/pending реальная.
5. Reduced motion отключает необязательные плавные прокрутки/переходы. Autoplay не добавлять.

Не объявлять соответствие всем WCAG по одному скриншоту. Проверяемые критерии: WCAG Contrast Minimum, Reflow, Target Size Minimum, Focus и Keyboard. Источники: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html ; https://www.w3.org/WAI/WCAG22/Understanding/reflow.html ; https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html .

## 12. Принцип переноса

**Меняется внешний слой и визуальная рамка; рабочие алгоритмы не переписываются.** Настоящий API вместо fixture, существующий React вместо hash/CSS-router, настоящий media player вместо обложки, реальный enum реакций вместо checkbox, старые guards вместо выдуманных permissions.

Если точное изменение конфликтует с доказанным техническим инвариантом, сохранить инвариант и принести конкретный diff/сценарий владельцу; не маскировать конфликт «похожим» интерфейсом. Все неизвестные состояния сначала привязать к существующим компонентам из IMPLEMENTATION, не изобретать новую архитектуру.
