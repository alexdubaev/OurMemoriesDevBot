## Последнее решение владельца

Нижнее меню: **Лента → Альбомы → Добавить → Семья**. Альбомы — самостоятельная вкладка, в том числе для Viewer. «Добавить» — действие, не постоянный выбранный экран. Для Viewer сохраняется текущая недоступность публикации; третья позиция может показывать существующий режим «Просмотр», но не активный submit.

Первая версия содержит четыре структуры: **Первый год**, **Первые открытия**, **Мастерская**, **Свободный альбом**. Мастерская — плотная галерея по годам/месяцам с масштабами 8/5/3 базовых колонок, а не выставка больших подписанных карточек.

Их содержимое не является эталоном production assets. Полноцветный HTML с исходными демонстрационными изображениями передан в чате отдельно.

## Предварительная оценка маршрута

**Для этого документационного PR:** docs/reference only, runtime не меняется, deploy не нужен.

**Для реализации:** FULL, не FRONTEND. Появляются долговременные семейные альбомы, контракт/API, таблицы и миграция, проверка доступа к существующим медиа. Один новый пункт меню не превращает весь diff в presentation-only. В ходе разработки — узкие проверки; FULL на готовом точном source согласно текущим guards. Не повторять FULL после каждого CSS-изменения.

Минимальный объём: новые albums module/contracts/UI + четыре пункта действующей навигации + тонкие адаптеры существующих media picker/upload/viewer. Не менять текущую ленту, auth/F12, MAX, comments/reactions, импорт, авторство, media lifecycle, SW и семейные роли. Не внедрять multi-child и межсемейный обмен одновременно.

Главные затраты/блокеры: корректная additive migration; доступ к disposable `*_test` PostgreSQL/storage; совместимость с уже работающими приватными медиа разных видов; применение FULL и реальная recovery readiness. В production не создавать демоальбомы и не запускать автоматические тестовые записи.

Стандартная автономность и полномочия на PR/merge/разрешённый deploy — по актуальному AGENTS.md. Этот docs PR сам не является разрешением немедленно выкатывать прототип. Не создавать новую preview-платформу, не менять процесс выпуска и не использовать старые одноразовые shell-операторы из чата.
