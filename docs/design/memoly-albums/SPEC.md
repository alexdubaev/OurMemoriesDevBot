# Альбомы memoLy · продуктовая и UI-спецификация v1

## 1. Результат и границы

В существующем React-приложении появляется рабочий раздел «Альбомы» с настоящими семейными данными. Владелец и Full собирают истории из существующих воспоминаний и новых загрузок; Viewer просматривает. Никаких JS/localStorage-альбомов вместо серверного хранения. Только MAX / MAX Mini App / Web/PWA с MAX authentication.

В scope: каталог, создание/изменение/удаление альбомов, четыре вида, главы, выбор конкретных фото/видео из существующих публикаций, текстовые события, мастерская большого объёма, просмотр, настоящие ошибки/повторы, навигация. Вне scope: распознавание лиц, многодетная миграция, отметки чужих детей, «Нас отметили», новые права обмена, публичные ссылки, AI, PDF/печать, игровые награды, отдельные birthday/seasons templates, новые комментарии/лайки альбомов, новый SW/offline архив. «Три свечки» в демо — свободный альбом, а не пятый шаблон.

## 2. Нижняя навигация

Порядок для Owner/Full: **Лента | Альбомы | Добавить | Семья**. Четыре равные колонки. На ширине 320px ничего не обрезается и не переносится на две строки. Вся область кнопки ≥44×44 CSS px. Сохранить текущую компактную высоту около 50px при базовом тексте и текущий адаптивный safe-area, учтённый один раз. Не возвращать 62/96px и большую нижнюю пустую полосу. Не менять итоговое принятое выравнивание иконок при добавлении четвёртой колонки.

«Альбомы» активны в каталоге, шаблонах, конкретном альбоме, месяце, событии и мастерской. «Добавить» открывает существующий composer; после закрытия возвращает исходный раздел. Специфические действия «Добавить работу/воспоминание/создать альбом» находятся внутри альбомов; глобальный плюс не должен неожиданно становиться кнопкой нового альбома. Viewer видит вкладку альбомов и прежний неактивный для публикации центр. Лента и Семья сохраняют свои маршруты и scroll position.

Back: viewer → исходная плитка; редактор/выбор медиа → соответствующая глава; глава → альбом; альбом/выбор шаблона → каталог. На верхнем уровне применить существующее MAX Back-поведение, не отправлять пользователя наружу случайным `history.back()`. Смена семьи/аккаунта закрывает вложенные экраны прежнего scope.

## 3. Каталог и создание

Заголовок «Альбомы», действие «Создать альбом», фильтры «Все / По шаблону / Свои». Показывать только реальные альбомы выбранной семьи: обложка, название, число работ/историй либо заполненных месяцев. Empty state предлагает первый альбом и выбор шаблона; не создавать автоматически четыре пустых альбома.

Создание: выбрать тип → название → существующий ребёнок или семейный контекст (для свободного) → необязательное описание/обложка → сохранить. Название 1–80 Unicode code points после trim; описание до 2000. Не добавлять новые детские профили из этой формы: используются текущие реальные профили/API. Демонстрационные Лилия/Миша не означают требование внедрить поддержку нескольких детей сейчас. Если ребёнок не настроен, существующий onboarding либо понятное недоступное действие для child template; свободный семейный альбом доступен при действующих правах.

Создание сразу открывает реальный альбом. Не требовать медиа для создания. Обложка — выбранное доступное вложение, иначе первое подходящее, иначе штатное оформление шаблона. Отсутствие картинки не ломает размер плитки. Обновление шаблона в будущем не перестраивает старый album без явного решения: templateVersion=1.

## 4. Первый год

Один экземпляр для существующего ребёнка. Ровно 12 неизменяемых по номеру слотов 1…12. Название «Первый год …», вертикальная временная линия и обзор «Все 12 месяцев». Не добавлять обязательный нулевой/тринадцатый слот.

Смысл слота: «Нам N месяцев», выбранный портрет/момент соответствующего возраста, а не медицинский норматив. Главы доступны для заполнения в любом порядке и задним числом. Будущие/пустые месяцы не отмечать ошибками. Пустая глава компактна; заполненная показывает главный кадр/видео-обложку, короткий текст и количество дополнительных материалов. Нет необходимости иметь точную дату рождения, чтобы вручную выбрать фото. При известной дате показывать подсказку возраста, но не навязывать точное попадание в день.

В слоте: необязательные название до 120, история до 8000 code points, дата/период, несколько выбранных материалов, один главный. «Выбрать из воспоминаний» открывает семейный picker; «Загрузить новое» использует существующий upload/composer. Можно заменить главный, добавить/убрать материал, изменить подпись. Заполненность = хотя бы один доступный материал ИЛИ непустая собственная история; одинаковый расчёт на клиенте/сервере. В обзоре 12 плиток, заполненные открывают главу, пустые — её заполнение. Замена cover/порядка не меняет исходную публикацию.

Никаких автоподстановок «первый шаг» по внешнему виду. Возрастные кандидаты в picker лишь подсказка по occurredAt и family timezone, не блокирующий фильтр. Вкладка «Все воспоминания» всегда доступна. Изменение birthDate не переносит вручную выбранные материалы между слотами.

## 5. Первые открытия

Хронология собственных событий: например улыбка, переворот, слово, зубик, шаги. Предложенные названия — стартовые варианты, можно добавлять свои и скрывать ненужные предложения. Нет ожидаемого возраста, обязательного порядка или процента «развития».

Событие: название 1–120, история до 8000, дата необязательна, материалы необязательны. Требуется хотя бы текст истории или один материал. Текстовое событие без фото — полноценная карточка, не сломанный placeholder. Поддержать точную дату, месяц, год и «Не помню дату» без выдумывания точного дня. Сортировка: известные периоды по возрастанию, внутри одинакового периода устойчивый ID; неизвестные — отдельный блок в конце. Формат периода должен быть видим пользователю; не обещать более точный порядок, чем данные.

## 6. Мастерская v2 — главное отличие

Плотная галерея рисунков, аппликаций, пластилина, построек и других работ. Не переносить старый вариант из двух отдельно подписанных карточек с большими полями.

Группы: год → месяц, новые сверху; неизвестная дата — «Без даты» в конце. Дата работы задаётся при добавлении/редактировании; значение по умолчанию — реальная дата выбранного воспоминания, не дата импорта MAX. Все значения локализуются в timezone семьи без UTC-сдвига календарного дня.

Три уровня: **Обзор 8**, **Коллаж 5** (по умолчанию), **Крупно 3** базовых колонок. Акцентные плитки могут занимать больше одной ячейки. Между плитками 3px, без внешних карточек, поворотов, бумажных рам и постоянно видимых названий/дат/цитат. Комбинация квадратных, портретных и горизонтальных плиток из metadata/детерминированного layout. Не случайное перераспределение при каждом render. Порядок чтения и viewer совпадает с реальной хронологией, не `dense`-переупорядочивание.

В compact gallery допустим визуальный preview crop; это НЕ изменение оригинала/crop данных. Полное изображение в viewer всегда contain, без обрезки. В отсутствие metadata рамка заранее стабильна. Не скачивать оригинал ради размера. Фото поделки — главное; текст открывается по нажатию. В режимах масштаба состояние и scroll anchor сохраняются.

Управление масштабом: кнопки −/+ с доступными названиями и жест двумя пальцами в зоне галереи. Один палец прокручивает страницу. Разведение увеличивает плитки, сведение уменьшает. Сохранить работу возле центра жеста; после жеста не должно срабатывать случайное открытие плитки. Жест не перехватывает системный масштаб на формах/остальной странице и не конфликтует с pinch фото в viewer. Не добавлять `user-scalable=no`.

Быстрый переход к году, фильтр категории, восстановление позиции при закрытии работы. Категории v1: Все / Рисунки / Аппликации / Поделки / Постройки; категория «Другое» допустима для формы. Поля работы: фотографии (≥1), необязательные название/дата/категория/описание/слова ребёнка. При пустом названии выводить fallback только в detail, без обязательной подписи каждой плитки.

Массовое добавление: несколько выбранных фото по умолчанию → несколько отдельных работ с возможностью уточнить позже; несколько ракурсов одной поделки можно объединить в одну работу. Не копировать одни и те же медиа; повтор добавления того же источника в ту же работу идемпотентен. Новая загрузка наследует реальные лимиты текущего upload и обрабатывается ограниченными порциями, не отдельным unrestricted uploader.

Демо 224 работ в 2024–2026 — нагрузочная выборка, не production seed. В production API отдаёт страницы, а не весь многолетний архив. Миниатюры грузятся lazy, оригиналы/видео — только при необходимости. Перестроение размера не должно перемонтировать все медиа-проигрыватели ленты.

## 7. Свободный альбом

Название, описание, обложка, ordered entries с выбранными фото/видео и необязательными историями. Обычная качественная галерея, без искусственных месячных слотов и milestone-прогресса. Добавить, убрать, изменить порядок; на телефоне доступна явная перестановка/кнопки как альтернатива drag. Сохранение порядка атомарно и защищено expectedVersion.

«Поездка к бабушке», «Цирк», «День рождения» создаются этим видом. Отдельные дизайнерские движки для каждого названия не нужны.

## 8. Выбор медиа, загрузка и оригиналы

Picker использует доступные воспоминания выбранной семьи, умеет выбирать конкретное вложение карусели. Фото/видео остаются по своим исходным ID и приватным endpoints. Несколько воспоминаний можно выбрать в одну главу; один исходный файл может участвовать в нескольких альбомах без копии bytes.

Для текстовой заметки/голоса использовать существующий Memory как ссылку на воспоминание в главе (без искусственного photo ID); в мастерской обязательна фотография работы. Голос проигрывается реальным существующим player, не mock progress. Поиск в picker — только scoped server query по body/метаданным либо явно «по загруженным»; не загружать весь архив для поиска. Фильтры и pagination сохраняют выделение по устойчивым ID.

Новая загрузка в v1 проходит существующую публикацию Memory и затем связывается с альбомом. Пользователю явно показать: «Будет сохранено в семейную ленту и этот альбом». Не разрабатывать скрытое album-only storage и новую квоту. Уже опубликованная запись при failed album attach сохраняется; retry выполняет только attach с тем же operation key. При отмене незавершённой загрузки работает существующая очистка reservation. Ошибки частичного batch показываются отдельно, успех не повторяется.

«Убрать из альбома» удаляет только связь. «Удалить альбом» удаляет структуру/связи, но не Memory/media. Удаление исходного Memory через штатный путь прекращает выдачу из альбомов, thumbnail и playback; не сохранять обходную ссылку. В editor можно показать недоступную связь и убрать её. Внешние grant/«Нас отметили» не импортировать и не превращать в постоянную копию.

## 9. Доступ и общие состояния

Album.familyId — граница доступа. Все активные участники семьи читают. Owner/Full создают/редактируют/удаляют альбомы и их связи, Viewer — нет. Это применение существующих ролей к новому ресурсу, не расширение полномочий существующих Memory/users. Нельзя прикрепить объект другой семьи, угадать UUID чужого альбома, передать URL вместо ID или получить оригинал после revoke.

Обязательные состояния: loading с фиксированной геометрией, empty, error/retry, offline без ложного success, pending submit, version conflict, частичный batch, committed save + failed refresh, недоступный original, доступ отозван. Server success отдельно от read refresh: повтор чтения не создаёт второй альбом/работу. При смене семьи/аккаунта abort запросов и защита от позднего результата. Read-only Viewer не видит mutation controls, сервер всё равно проверяет права.

## 10. Внешний вид и сохранение текущего продукта

Эталон размеров/состав экранов — reference-source; фиктивные снимки/даты/счётчики/имена не являются требованиями к данным. Применять текущую Typography и semantic theme tokens, WebpIcon, текущие sheets/dialog/focus/MAX Back. Демонстрационные SVG icons не переносить в production напрямую. Размер ввода 16px, hit44, text200% без потери доступа. Поддержать текущие темы, не делать глобальный редизайн.

Не переносить из прототипа demo reset, export HTML, random IDs, localStorage JSON, собственный hash-router, копии семейного экрана/ленты, fake video/like counters, второй ребёнок и все-renders-в-DOM. Приоритет текущих алгоритмов выше демообвязки.

Сохранить карусели/fullscreen, стабильную media frame и отсутствие схлопывания, shared avatar, остановку/освобождение видео, author attribution, реальные реакции/комментарии, даты MAX, дедупликацию, семейную ACL/F12, profile crop, имена, приглашения и текущий nav safe-area.
