## Accepted architecture and technical rulings

One small features/comments module, existing AuthenticatedTransport, TanStack Query and contracts; API list/create/update/delete/summaries only. No backend/contracts/MemoryDto/auth architecture/dependencies/media-engine changes. No plaintext persistence or growing drafts map.

1. Privacy keys use a SEPARATE ['session','comments',familyId,accountId,membershipEpoch,...] namespace, including memory for lists. Do not put comments under ['session','feed']: existing feed cache helpers assume MemoryPage and would process comment data incorrectly. Session cleanup already removes session descendants; minimally extend removePrivateFamilyCache to cancel/remove matching comments keys as well as its existing feed cleanup. Existing isPersistableQueryKey excludes comments; preserve whitelist. No comments text added to persistent-ui or feed DTO.
2. All asynchronous query/mutation/summary cache writes require current account/family/epoch plus mounted discussion lease and existing private identity/family generation. Cancel HTTP/query where possible on close/scope loss, but never treat Abort as server rollback. Old requests (even a transport ignoring AbortSignal) must not repopulate caches or drafts. On account/family/epoch/session change, revoked-family event or inactive feed, force-close/unmount without dirty prompt; remove old scoped comment data. Ordinary close clears list/draft/pending editor state for that discussion; summary metadata may remain transient. Feed selection stores scope with memoryId and renders only if current, then resets on context change, preventing reopening old panel on returning to old context.
3. Summaries are batch POST groups<=50 of loaded/needed Memory IDs, no per-card count queries, no polling. Unknown/error count is undefined, never a fabricated0. Positive count visible, known0 icon-only; accessible label includes known count including0. Lists enabled only for open discussion. Refetch on open/open-panel focus/manual refresh/own confirmed mutations; no background list refetch after close. Update scoped summaries from authoritative mutation response; invalidate active list without resetting feed. No optimistic success or draft clear before server response.
4. Composer: multiline plain text/systememoji, font>=16px, explicit submit only, Enter newline and IME safe. Shared commentBodySchema normalization. A synchronous busy ref prevents double submit. One attempt captures immutable normalized payload+UUID key. Network/timeout/abort with unknown outcome retains that exact attempt and draft; retry uses same key/body. Lock text while uncertain with clear explanation/retry. Do not send edited text under old key. Conclusive server rejection may unlock draft/new attempt only after showing error; no auto retries. Clear only on confirmed success. Dirty normal close asks Continue writing/Close without saving; pending/uncertain close explains that request may have saved. Forced privacy close discards without prompt.
5. One panel, one current composer and one edit draft (no per-post map). Chronological display sorted createdAt/id, dedupe pages by id/version; fetch older pages at top and compensate scrollHeight to preserve read anchor. Own success may scroll message list, never feed. Display human author/name/private avatar crop and edited marker version>1. Use existing FeedSharedAuthorAvatars/FeedAuthorAvatar public components directly (no relocation/refactor) to dedupe comment avatars; it already uses private loader and crop. Never channel attribution for comments.
6. PATCH uses current expectedVersion; conflict preserves edit draft, refreshes server text/capabilities, shows conflict and requires another explicit save; never automatic overwrite. DELETE uses numeric If-Match + confirmation/cancel, busy guard, response refreshes list/count. Buttons use server capabilities only, never role guesses. On operation403 ROLE_FORBIDDEN refresh capabilities/show error; it does not prove family read access loss. Read403/404 after a prior successful list means target access lost: clear/force-close only that target. Initial404 is ambiguous (old API or vanished post): neutral comments error+retry, no global disable or invented backend-version probe. Write404 can be missing comment: refresh list; forced closure only when read access loss confirmed. 401 follows existing auth recovery; no new auth layer.
7. UI uses existing controlled Dialog/BottomSheet primitives and v4 tokens/typography. Visible close, loading/error/retry/empty states. Empty copy exactly 'Пока нет комментариев. Напишите первым'; textarea 'Написать комментарий…'. All controls>=44px, safe-area and keyboard-aware available viewport. Existing MemolyBottomSheet/Vaul may be reused with real Title/Description; no global preventDefault/user-select/touch-action. Text selection remains native inside field.
8. Close/history: own a single same-URL history entry with unique token, HostBridge.onBack subscription and popstate listener, cleaned on unmount. Only pop owned current entry once, never double history.back. Dirty browser-back may restore owned entry while confirmation pending; Continue retains discussion, discard closes. Nested delete/dirty confirmation gets priority on Escape/host back. Restore trigger focus with preventScroll when still connected. Forced context changes do not navigate back into old family/location. Preserve media attachment index and feed scroll.

Integration stays small: FeedPage selected scoped Memory/ref, summaries hook, single panel and callbacks; MemoryCardPresentation callback/count/button only in feed mode; MemoryReactions adds only adjacent action slot/group, preserve selection/label and44px controls. Plain comment button22px currentColor WebpIcon (name comments), icon+optional count vertically centered, no plate/shadow/circle/text. Ordinary footer remains compact; many reactions wrap at320. Include comments overlay in seen-observer blocked flag. Do not add entry over fullscreen or change media engines/nav.
