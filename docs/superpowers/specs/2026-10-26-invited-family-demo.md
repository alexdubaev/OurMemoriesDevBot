# Знакомство приглашённых с memoLy

Task INVITED-FAMILY-DEMO. Base 6fe28159adef0b8abd854b8aaeca8fe678087864; branch feat/invited-family-demo.

Пользователь выбрал демонстрацию готового альбома и подробную инструкцию для приглашённых и поручил реализацию. Уточнение пользователя: «презентация должна точно соответствовать моему интерфейсу», без вымышленных интерфейсов. Это обязательное требование: демонстрация использует реальные компоненты production, а не их визуальную копию. Примерными остаются только материалы семьи.

В MAX-сценарии IncomingInvite сначала показывает знакомство. Можно сразу вернуться к проверенному приглашению; только существующая кнопка «Присоединиться» вызывает onAccept. Настоящая семья и её медиа не передаются в демонстрацию. Примерные материалы и локальные реакции/бронь не сохраняются. После вступления повторный вход доступен в «Семья» → «Как пользоваться memoLy».

Лента использует FeedPresentation, MemoryCardPresentation, MemoryList, MemoryActions/Content, PhotoImage и настоящий MixedMediaViewer. Альбомы и вишлист используют общие с рабочими страницами presentation-компоненты. Full видит настоящее AddSheetPanel/VoiceOrVideoPanel; загрузки в демонстрации заменены пояснением следующего шага. Viewer видит свою настоящую навигацию. Отдельный интерфейс создаётся только для учебных подсказок поверх продукта и подробной справки. Подсказку можно свернуть. Голос и видео объясняются без поддельного воспроизведения. Комментарии в демонстрации открывают инструкцию; реакция действует локально через реальный механизм выбора.

Справка объясняет приглашение, ленту, медиа, реакции и комментарии, альбомы, вишлист, добавление для full, ошибки и приватность. Голосовые добавляются через бот MAX, а не через вымышленный аудиоредактор.

Не меняем App bootstrap, MAX/browser-link auth, token lifecycle, legacy browser autoaccept, серверные ACL, API, хранилища и реальные данные. Старый browser-путь сохраняет поведение; повторная справка доступна в семье. Нет новых зависимостей и внешних медиа. Используем существующие demo assets и текущую тему приложения. Демонстрационный viewer получает static photo URL и transport, который отклоняет любые API-вызовы.

Allowed paths: FamilyGuide.tsx, family-guide.css, InvitationScreens.tsx; FamilyPresentation.tsx; FeedPage.tsx только export существующих чистых компонентов; features/albums и features/gifts только выделение shared presentation без изменения поведения; существующий max-family-audit.max-e2e.ts; spec/plan; .autopilot/PROGRESS.md. Backend/schema/lockfile/auth/API запрещены.

Проверка: STANDARD typecheck/lint/build, webapp unit suite, существующий MAX family audit с изолированной тестовой БД и синтетическими аккаунтами. Проверить отсутствие вступления/доступа до явного согласия, nested dialogs/focus, роли, повторный вход, отказ сервера и retry, mobile/desktop. Независимое Luna review. Реальный MAX/iPhone и production не утверждать проверенными.
