# 02 — Сервер: добавление, правка и удаление детей, альбомы по ребёнку

**Требования:** R01, R02, R03, R13, R34
**Зависит от:** 01
**Зона:** `backend/src/modules/families/` · `backend/src/modules/albums/` · `backend/src/modules/media/` (только если нужно для аватара нового ребёнка)
**Волна:** 2
**Ревью:** да — удаление пользовательских данных (профиль ребёнка) и права владельца
**Модель:** сильная

## Что должно заработать

Владелец через API добавляет в семью ещё детей, правит профиль любого из них и удаляет ошибочно созданный профиль. Ответ семьи по заголовку `X-Memoly-Children: 1` отдаёт всех живых детей по порядку. Список альбомов фильтруется по ребёнку. Старые пути (`PUT /child`, `PATCH /families/:id` с полем `child`) работают со старшим по созданию живым ребёнком, как раньше.

## Из брифа, дословно

> «В одной семье можно создать несколько профилей детей.»
> «Добавлять и редактировать профили может владелец семьи.»
> «Используется существующая система альбомов memoLy, без создания дублирующей архитектуры.»
> Дополнение: «владелец может удалить профиль ребёнка, пока у него нет отметок и альбомов»

## Разделы спецификации

Истории 1–3, 5–8, 19 (серверная часть), 29. Решения: мягкое удаление, альбомы привязаны к ребёнку, заголовок. `interfaces.md`: «HTTP», «Термины».

## Критерии приёмки

- [ ] `POST …/children` создаёт живого ребёнка с полным профилем (имя, дата рождения не в будущем, пол, готовый аватар `child_avatar` этой семьи, квадратный crop); повтор с тем же Idempotency-Key возвращает того же ребёнка; 13-й живой ребёнок — 409 «В семье уже 12 детей»
- [ ] `PATCH …/children/:childId` правит любого живого ребёнка с проверкой `expectedVersion`; чужая версия — 409 VERSION_CONFLICT; замена аватара освобождает старый, как в существующем пути
- [ ] `DELETE …/children/:childId` с версией мягко удаляет ребёнка без отметок и без живых альбомов; при отметках, живом альбоме, активной сессии загрузки MAX-видео или если ребёнок последний живой — 409 с причиной по-русски; удалённый ребёнок пропадает из `children`, из фильтров альбомов и из выбора при создании
- [ ] Участник не владелец получает 403 на все три метода; чужая семья или ребёнок чужой семьи — 404; отозванный участник — 404
- [ ] `GET /families/:id` с заголовком отдаёт `children` в порядке детей; без заголовка ответ совпадает с прежним байт в байт по набору полей
- [ ] `GET …/albums?childId=` возвращает только альбомы этого ребёнка, курсор подписан с фильтром; ребёнок чужой семьи — 404
- [ ] Интеграционные тесты families и albums зелёные, включая существующие
