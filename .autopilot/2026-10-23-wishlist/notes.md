## 8. Миграции и схема

- Папки `backend/prisma/migrations/<YYYYMMDDHHMMSS>_<snake_case_name>/migration.sql`, плюс `migration_lock.toml`. Последняя: `20261020173000_memory_comments`; перед ней `20261003113000_max_video_thumbnail`, `20261002120000_user_avatar_crop`. Новая должна быть строго позже 20261020173000 (например `202610231xxxxx_gift_wishlist`). Применённые миграции не править (AGENTS.md §10).
- Стиль: SQL руками (не `prisma migrate dev`), аддитивный (expand), без бэкфилла; пример `20261020173000_memory_comments/migration.sql`: `CREATE TABLE`, `CONSTRAINT <table>_pkey`, именованные FK `<table>_<col>_fkey ... ON DELETE CASCADE ON UPDATE CASCADE`, `CHECK`, `CREATE UNIQUE INDEX`/`CREATE INDEX`. Enum-значения добавляются отдельной командой `ALTER TYPE`.
- Конвенции схемы (`schema.prisma`): таблицы snake_case через `@@map("memory_comments")`, колонки `@map("family_id")`; id `String @id @default(dbgenerated("uuidv7()")) @db.Uuid` (uuid v7 на стороне БД); время `DateTime @default(now()) @map("created_at") @db.Timestamptz(3|6)`, `updatedAt @updatedAt`; `version Int @default(1)` для оптимистичных блокировок; мягкое удаление `deletedAt`; FK с явным `map:`-именем; составные ключи `[id, familyId]` с `@@unique` для изоляции между семьями (`Memory`, `MediaAsset`, `Child`): FK `[mediaId, familyId] → MediaAsset[id, familyId]` гарантирует, что фото принадлежит той же семье. Автор через составной FK `[familyId, userId] → FamilyMember` (`MemoryComment.authorMembership`). Для новых моделей надо добавить обратные relation в `Family`, `FamilyMember`, `MediaAsset`, возможно `Child`/`User`.
- Генерация клиента: `backend/src/generated/prisma` (`generator client`, `schema.prisma:1-4`), команда `bun run --cwd backend prisma:generate`.
- Тесты миграции: рядом лежат upgrade-тесты `backend/scripts/*-upgrade.integration.test.ts` и `comments-release-compatibility.integration.test.ts` (граница релиза). Новая таблица без правки старых данных, обычно достаточно обычных интеграционных тестов модуля.
