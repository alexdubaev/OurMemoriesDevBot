# Спецификация: истории альбомов, обсуждения и акварель

## Задача и нормативный объём
Одна последовательная задача MEMOLY-ALBUMS-WATERCOLOR-AND-SOCIAL. Полный исходный 2026-11-04-brief.md разделы 0–11, включая все подпункты, — нормативная часть этой спецификации. Это объединённая реализация, а не UI-only. Ничего из брифа не откладывается и не заменяется предположением. API/границы/locks — interfaces.md; целевое чтение — notes.md. Сохраняем весь актуальный принятый main и чужую работу; одна новая task branch/worktree/implementation PR, общий выпуск, без промежуточного production.

## Истории и приёмка
1. Действующий Owner/Full/Viewer открывает одну историю AlbumEntry (work/month/event/free), читает с пагинацией, создаёт нормализованный комментарий 1–2000 Unicode codepoints без NUL, видит count/send/error/retry; после повторного чтения сохранено. Свой текст правит с optimistic version, свой комментарий удаляет; owner семьи удаляет чужой, но не редактирует его; full не модератор. Viewer не редактирует альбом.
2. Любой действующий участник ставит/заменяет/снимает одну из существующих шести реакций, heart один из enum. Upsert unique entry/user, повторная доставка не увеличивает count; очередь последовательных intent гарантирует финальное состояние быстрых taps. После перезапуска reaction/comment сохраняются.
3. Обсуждение — у всей работы, не у каждого фото, альбома или файла. Три ракурса имеют общий ряд. Одна история, открытая из списка, деталей или просмотра её медиа, всегда использует то же обсуждение. AlbumEntry обсуждение не пересекается с memory feed; один файл в двух записях имеет два обсуждения. Прямая album upload работает без фиктивного Memory/публикации в feed/MAX и без использования display-only viewer ID в API.
4. Сервер проверяет live user/session/member/family/album/entry/deleted state внутри real PostgreSQL transactions. Composite FK подтверждает цепочку family→album→entry, чужая семья/альбом/запись недоступны. Отзыв членства одновременно с записью/чтением сериализуется; старая сессия не может читать/create/edit/delete/react после отзыва. Счётчики удалённого объекта не видны. UI/cache старого приватного scope очищаются.
5. Existing MemoryComment/MemoryLike и DTO/API/данные не меняются; переиспользуются validation/idempotency/pagination/errors/author projection/reaction primitives без универсальной платформы. New additive migration и scoped album APIs строго определены interfaces.md; cursor/signature/target/family/generation namespaces не смешиваются. Durable idempotency key с другим телом/целью конфликтует, потерянный response retry не дублирует комментарий даже после executor TTL. Versions только comment/generation, реакция не конфликтует с обложкой альбома.
6. Edit/cover/media reorder сохраняют обсуждение. Delete entry/album закрывает его, не удаляет исходные media. Полная очистка month после явного подтверждения с понятным текстом о сбросе комментариев и реакций сбрасывает текст/связи и обсуждение/reactions, повышает поколение атомарно; новый контент не наследует старое обсуждение. Поздний request/retry/response старого поколения не возвращает комментарии в новую главу. Пустой month не считается заполненным из-за comments и social UI/API недоступны до истории. Text-only event с partial/unknown date полноценен.
7. После работающего API существующие CommentsPanel/CommentComposer/CommentItem и reaction picker подключены typed adapter к AlbumEntryDetail. Нет копии панели, entryId в memoryId или as/any masking. Query/draft/optimistic/retry identity account+family+epoch+type+target+generation. Scope switch aborts old reads, ignores stale responses, never transfers draft/cache. Сохранены unsaved warning, uncertain send retry, edit/delete, существующий polling refresh from other member, keyboard/safe-area/focus/MAX Back. Confirmed create плюс failed refresh не отправляется повторно.
8. Main social actions на открытой истории: компактные reactions + «Комментарии» count, один ряд для всех attachments. Нет постоянных panel/count/caption под workshop tiles, нет N+1 на 2000 works. Fullscreen viewer сохраняет media lifecycle и возврат в detail; его redesign не нужен.
9. После API и подключения UI перенести утверждённый ПЕРВЫЙ вариант полного memoly-albums-watercolor-nojs.html/ZIP (reference commit 863610b694c628df4e303032ce3833eeadcc6ea0, PR270), не schematic reference.html. Тёплый watercolor, palette, soft green hills, небольшой bear рядом с gallery и bunny внизу, plant details. Отдельные качественные оптимизированные neutral assets, без emoji-декора и screenshot UI. Реальные photos главные, большие intro/cover/add strips убрать, компактная шапка/back/menu/obvious add, description/settings secondary в menu. Controls не строят этажи. Существующие темы/читаемость и >=44px targets, 320px no overflow.
10. Workshop сохраняет dense collage/year-month/category/8-5-3/pinch/zoom buttons/virtualization/pagination/scroll anchor; collage не становится feed cards. Первый год сохраняет 12 durable chapters, actual fill, compact history/all months toggle, фото в filled и compact empty. Первые открытия сохраняют photos/short titles/dates, text-only/partial unknown dates/suggested/custom add. Free gallery сразу после короткого heading, source/order/editor сохранены.
11. Album catalog НЕ редизайнить: AlbumCatalogPresentation/family banner/covers/filters/children grouping/catalog scroll те же. Нижняя nav Лента→Альбомы→Добавить→Вишлист→Семья. Не добавлять album-wide/per-attachment discussions, threads/mentions/attachments, MAX notifications/mailings, sharing/Нас отметили, ratings/favourites/new emotions, infra/libs/messengers. Не менять auth/roles/import dedupe/authorship/media storage/private endpoints/avatar crop/video/carousel/fullscreen/feed social behavior. Limited adapter only; без рефакторинга всей ленты.

## Последовательность доказательств
Сначала сервер без большой visual rewrite: targeted PostgreSQL persistence/3 roles/cross target/idempotency/reaction/clear-delete/revocation races. FULL отдельно после этого не нужен. Затем текущий album UI: direct photo/no Memory, feed source, text-only, three photos, separated discussions, return/scope. Затем watercolor четыре внутренних экрана + UI с теми же social controls.

Общая приёмка повторяет все 12 обязательных сценариев §8 брифа: (1) direct uploaded craft persistent social, (2) three photos one discussion, (3) feed discussion unaffected, (4) same file two entries separated, (5) year/text-only, (6) roles edit/moderation, (7) lost-response retry and confirmed send/failed-refresh, (8) rapid reaction change/null, (9) revoke/delete/clear/stale response, (10) family/account switch/MAX Back/keyboard/focus, (11) feed social regressions, (12) workshop 3/2000 bounded DOM/requests/zoom/return. Использовать synthetic материалы и собственные *_test DB/storage/ports/run IDs, явно проверить DATABASE_URL/TEST_DATABASE_URL без вывода секретов. No writes to real families.

Визуальная приёмка: 320/390/430px, увеличенный текст, empty/filled, реальные четыре внутренних экрана vs chosen full original; отдельно catalog before/after на одинаковых данных. MAX Mini App и Web/PWA MAX auth; desktop emulation не подтверждает физический iPhone. Скриншоты в task evidence, private family media не в Git. Оставить краткий реальный manual iPhone/MAX checklist.

Итоговый source требует FULL (new data/contracts/protected operations); targeted checks/type/lint/build в этапах, без full после CSS. Одно независимое technical review итогового diff: tables/API/ACL/transactions/replay/shared adapters/feed regressions, одна bounded fix pass и narrow closure. G2 independent brief coverage и G4 blind acceptance не технические повторные review. Обновить task docs от UI-only. Actual source-bound evidence, перенос только по действующему exact-tree policy; старый лог не проверяет новый source. Ничего не скрывать skips/dry-run/syntax-only PASS.

## Интеграция и выпуск
Fetch main, обычный merge origin/main при drift, разрешить реальные пересечения без reset/stash/rebase/force-push/чужих worktrees. Commit/push/один implementation PR/разрешённый squash автономно после gates. Проверить итоговый main, release SHA, синхронизировать локальную основную ветку только безопасно, не затронув её чужие ahead commits. Cleanup только собственных ветки/worktree после подтверждённого merge и чистоты.

До guarded единого FULL release: фактически работающие backend/frontend/jobs SHA, весь accumulated diff, migration old/new client compatibility, измеренная recovery (новые таблицы не доказательство additive-safe), backup/disk/host lock/immutable image IDs, не более нового чужого release, один release writer. Не снимать чужой lock, не менять guards/DB rollback/production data ради выпуска. Действующий S3 recovery путь по runbook, preserve accepted UI v4. Production smoke без создания comments/invites/deleting family records. При реальном blocker сразу точная причина, безопасная минимальная альтернатива; independent scope продолжается. Обычные merge/deploy заранее разрешены.
